# 同舟行跨境 v0.2.0

发布日期：待正式凭证联调和生产环境批准后确定。

## 本版交付

- 客户可在单个 24 小时草稿中按最多 20 个店铺分组上传 TEMU 原始 Excel，系统会在跨文件去重后按店铺生成独立拿货单，并把本次成功店铺合并进一个统一结算批次。
- 统一结算支持纯余额直扣、混合付款余额冻结、零余额线下付款和按订单金额比例分摊；管理员对一笔统一付款声明只确认一次，拒绝、撤回和超时都会原子释放冻结金额与关联库存。
- 批量提交、统一结算核款和极风 worker 重试都带真实幂等保护，避免重复扣款、重复锁库和重复推单。
- 账号治理升级为受保护超级管理员模型：系统 bootstrap 只创建一个超级管理员；账号管理只能创建普通管理员；普通管理员不能进入账号管理，也不能创建、停用、降级或升级超级管理员。
- 客户维持一人一号并可管理多个店铺；账号、客户和店铺全部采用软停用；停用账号会立即撤销全部会话。
- 管理员后台与客户门户统一切换到商家中心 UI，登录页文案、双端退出登录和全站本地字体令牌已经落地，同时保留既有单店导入、单店付款和履约流程。
- 最终门禁已覆盖客户隔离、账号治理、Secure Cookie 矩阵、统一结算只读越权、PII 脱敏、并发扣款与库存一致性，以及桌面和 360/390/430px 关键流程。

## 兼容与保留

- 原有单店 TEMU Excel 上传入口继续可用，没有强制迁移到批量草稿。
- 原有单店付款与履约链路继续可用，统一结算是新增能力，不替换历史订单流程。
- 极风、飞书未配置正式凭证时会安全停用后台任务，不阻断本地和测试环境的核心下单、库存与支付逻辑。

## 已确认延期

- TEMU API 直连拉单；本版继续使用后台导出的原始 Excel。
- 正式补货审批单；当前仍由管理员手工调整库存并填写原因。
- 线上充值/支付；当前继续使用余额管理和线下微信付款。
- AI 货品筛选、行业资讯、广告费与平台佣金核算。

## 正式上线前外部条件

- 极风正式域名、client id/secret、access/refresh token、user id、加拿大仓库编号、加拿大邮政渠道 ID，以及补发接口的正式字段与回调契约。
- 飞书企业自建应用 app id/secret、货盘知识库协作者权限、电子表格权限和内部机器人群。
- 正式 HTTPS 域名、PostgreSQL、Web/Worker 常驻进程托管、日志采集、监控与加密备份存储。

## 已知运维说明

- `npm.cmd run worker` 必须与 Web 同时常驻，否则订单超时释放、统一结算超时、极风对账和飞书同步都不会自动执行。
- 批量草稿过期不是定时删除任务，而是领域服务在读写时按 24 小时 TTL 切换为只读过期状态。
- 极风对账采用 claim token + `locked_at` 租约回收策略，避免 worker 崩溃后出现重复查单或重复创建。

## 已知安全说明

- 验收时 `npm audit` 剩余 4 个 moderate，全部来自 direct devDependency `drizzle-kit` 及其 `@esbuild-kit/* -> esbuild` 开发服务器链路，不在 Web/Worker 生产运行路径中。
- 建议修复路径是把 `drizzle-kit` 切换到 `0.18.1`，这属于破坏性的主线回退，不适合在验收阶段盲目调整；生产环境应继续确保不暴露任何开发服务器。
- `.env.example` 只保留占位值，真实极风与飞书凭证必须放在部署平台 secret 管理中。
