# 同舟行跨境 TEMU 订单、拿货单与结算 Implementation Plan

**Goal:** 客户选择名下店铺上传 TEMU 原始订单 Excel，系统完成预览、去重、SKU 映射、成交价计算、库存锁定、余额自动扣款或线下核款，并为后续疾风履约生成结构化包裹。

**Architecture:** PostgreSQL 是订单、资金和库存锁定的唯一真实数据源。原始导入先进入客户隔离的临时批次，提交时在单个数据库事务内创建拿货单、包裹和明细、锁定库存并决定支付路径。钱包余额使用行锁和不可变流水；订单状态只能通过领域服务迁移。

**Source workbook findings:**

- TEMU 原始文件 `订单导出2026811003.xlsx`：1 个工作表、33 列、15 条数据；关键列为 `订单号`、`子订单号`、`应履约件数`、`SKU货号`、收件人及地址字段。文件不含店铺名称，因此上传前必须选择客户名下店铺。
- 人工履约文件 `temu渥太华0811-35票50单-南京.xlsx`：1 个工作表、16 列、35 条数据；字段是从 TEMU 原始文件转换出的疾风/仓库包裹结构，不作为系统输入源。
- 去重键固定为 `(storeId, 子订单号)`；同一 `订单号` 的多条子订单行合并为一个外部包裹。
- `SKU货号` 只做精确别名匹配，不猜测后缀或自动改写。未知别名必须在预览中阻止提交。

**Timing:** 余额不足提交后锁库存 2 小时；客户声明已线下付款后延长到 12 小时等待管理员核款。

## Task 1: 订单、包裹、导入批次、钱包与付款 schema

- [x] 先写数据库约束测试：店铺与客户必须匹配、子订单在同一店铺唯一、金额和数量为非负整数、钱包只有一个客户账户。
- [x] 建立 `order_import_batches`、`order_import_rows`、`fulfillment_orders`、`order_shipments`、`order_lines`、`wallet_accounts`、`wallet_transactions`、`payment_claims`。
- [x] 订单状态包含 `PENDING_PAYMENT`、`PAID_PENDING_FULFILLMENT`、`CANCELLED`、`EXPIRED`，并预留阶段 3 的 `FULFILLING`、`SHIPPED`、`FULFILLMENT_EXCEPTION`。
- [x] 钱包流水包含 `ADMIN_CREDIT`、`ADMIN_DEBIT`、`ORDER_DEBIT`、`ORDER_REFUND`，保存 before/delta/after。
- [x] 生成迁移并同时应用开发库和测试库。

## Task 2: 敏感收件信息保护与 TEMU Excel 解析

- [x] 写失败测试覆盖 AES-GCM 加解密、错误密钥拒绝、日志/错误中不出现姓名、电话和地址。
- [x] `PII_ENCRYPTION_KEY` 为必需环境变量；收件姓名、电话、邮箱和完整地址只以密文保存。
- [x] 用 ExcelJS 读取 `.xlsx`，严格校验 33 列 TEMU 表头、文件大小、行数、订单号、子订单号、数量和加拿大地址。
- [x] 解析结果分为 `READY`、`DUPLICATE`、`UNKNOWN_SKU`、`INVALID`，并生成成功/重复/错误统计。
- [x] 增加真实匿名化夹具，验证原始表中同一订单的多子订单能合并为一个包裹。

## Task 3: 客户隔离的上传与预览

- [x] 客户只能选择自己的启用店铺；服务端再次调用 `assertStoreOwnership`，不信任表单中的 customerId。
- [x] 上传批次保存文件 SHA-256、原文件名、行数和过期时间；同一文件可以重新预览，但不能重复提交子订单。
- [x] 客户页面显示成功、重复、未知 SKU、格式错误四类结果；未知 SKU 显示原始 `SKU货号`，不暴露其他客户映射。
- [x] 管理员可在商品页补充别名后重新解析失败批次。

## Task 4: 原子提交拿货单与库存锁定

- [x] 并发测试证明两个拿货单不能锁定同一件末库存。
- [x] 提交时按 SKU 聚合数量，逐个调用 `reserveInventory`；任一 SKU 不足则整个事务回滚。
- [x] 每条订单明细保存提交当时的实际成交单价和行金额，后续改价不影响历史订单。
- [x] 创建拿货单、包裹、明细、库存锁定和审计记录必须在一个事务内完成。
- [x] 重复提交同一批次返回原拿货单，不创建重复流水。

## Task 5: 钱包余额与自动扣款

- [ ] 写并发测试证明钱包不会重复扣款或出现负余额。
- [ ] 管理员可增加或减少客户余额，必须填写原因；每次变更写钱包流水和审计。
- [ ] 提交拿货单时锁钱包行：余额足够则自动扣款并进入 `PAID_PENDING_FULFILLMENT`；余额不足不扣款，进入 `PENDING_PAYMENT` 并锁库存 2 小时。
- [ ] 钱包扣款以人民币分整数保存；订单保存 `paymentMode=WALLET` 或 `DIRECT_OFFLINE`。

## Task 6: 线下付款声明、管理员核款、取消与超时

- [ ] 客户可对待付款拿货单声明微信已付款，填写金额和备注，库存锁延长到 12 小时。
- [ ] 超级管理员确认后直接将订单改为 `PAID_PENDING_FULFILLMENT`，不把该笔钱先充值进钱包再扣款。
- [ ] 管理员拒绝付款声明必须填写原因；客户页面显示拒绝原因和剩余锁定时间。
- [ ] 客户/管理员取消订单必须填写取消原因；释放库存；钱包已扣款订单原路退回钱包并写退款流水。
- [ ] 超时服务使用幂等任务把未付款订单改为 `EXPIRED` 并释放库存。

## Task 7: 客户拿货单 UI

- [ ] 客户导航启用“上传 TEMU 订单”“我的订单”“待付款”“余额与流水”。
- [ ] 上传流程为：选择店铺 → 选择 Excel → 预览统计与错误 → 确认提交。
- [ ] 页面同时适配桌面表格和 360/390/430px 手机卡片；上传、提交、声明付款触控目标不小于 44px。
- [ ] 我的订单显示拿货单号、店铺、包裹数、件数、实际金额、付款状态、库存锁定倒计时和取消原因。
- [ ] 余额页显示余额、不可变流水及关联拿货单。

## Task 8: 管理员订单、收款与余额 UI

- [ ] 管理员导航启用“订单管理”“收款与余额”。
- [ ] 订单页支持状态、客户、店铺、日期和拿货单号筛选，显示异常优先队列。
- [ ] 收款页分为待核款、钱包账户、资金流水；确认/拒绝使用确认对话框并显示影响金额。
- [ ] 所有服务器操作调用领域服务并返回中文字段错误，不在页面文件直接更新订单或余额。

## Task 9: 阶段 2 验收

- [ ] 用匿名化的真实 33 列 TEMU 文件验证解析、去重、未知 SKU 和多行订单合并。
- [ ] 端到端验证余额足够自动扣款、余额不足线下核款、取消退款和超时释放四条路径。
- [ ] 运行单元、数据库集成、桌面/手机 E2E、axe、视觉快照、类型检查、lint 和生产构建。
- [ ] 更新本地运行手册和阶段 2 状态机说明后提交。

## Phase 2 Definition of Done

- 客户可以从 TEMU 原始导出直接生成结构化拿货单，不再人工整理 16 列履约表。
- 同一店铺子订单不会重复导入，未知 SKU 不会猜测映射。
- 提交时库存原子锁定；余额足够自动扣款；余额不足进入线下核款。
- 取消、退款、超时、钱包变更和管理员核款均有不可变流水与审计。
- 收件人敏感信息加密保存，客户只能访问自己名下订单。
- 全部质量门禁通过，桌面和三种手机宽度完成真实浏览器验收。
