# 同舟行跨境极风履约、补发与飞书集成 Implementation Plan

**Goal:** 将已付款拿货单按包裹幂等推送极风 WMS，同步加拿大邮政运单、费用与发货状态；极风确认发货后才正式扣减货盘库存；支持有原因、有明细、有审计的补发；把数据库货盘同步到飞书表格，并把履约异常与库存预警推送到内部飞书群。

**Architecture:** PostgreSQL 继续作为唯一真实数据源。极风和飞书都通过端口接口接入，领域服务不直接依赖 `fetch`。待处理任务使用 pg-boss；每次外部调用都有稳定幂等键、尝试次数、下次重试时间和脱敏错误。极风状态以查询接口和已验签 Webhook 双通道收敛，只有 `status=7` 进入已发货。飞书表格只是数据库的只读镜像，不能反向修改库存。

**Official contract findings:**

- 极风业务接口均为 JSON POST；请求头包含 `clientId`、`accessToken`、`timestamp`、`nonce`、`userId`、`sign`。签名原文由七个公共参数按键排序后以 `&` 连接，使用 `client_secret` 做 HMAC-SHA256。
- 创建订单 `POST /api/order/create`；查询订单 `POST /api/order/get`；取消订单 `POST /api/order/cancel`。同一客户下 `erpNo` 不可重复。
- 查询状态：1 待移货、2 待生成、3 待拣货、4 待包装、5 包装中、6 待发货、7 已发货、8 异常、9 已取消、10 获取中、11 获取失败；响应包含 `trackingNo`、`shippedTime`、`logisticsFee`、`currency`。
- 公开文档无独立“补发”端点。补发在同舟行系统中建模为 `REPLACEMENT` 包裹，并以新的稳定 `erpNo` 调用同一个创建订单接口。
- 飞书电子表格写入必须由应用或用户身份持有表格编辑权限；应用访问现有用户表格前需要所有者将应用添加为文档协作者。机器人必须加入目标群并具备发言权限。

## Task 1: 履约、补发、外部调用与飞书同步 schema

- [ ] 先写数据库约束测试：一个包裹仅有一条极风履约记录；`erpNo` 唯一；补发必须关联原包裹、原因和创建管理员；外部事件幂等键唯一。
- [ ] 建立 `shipment_fulfillments`、`replacement_requests`、`integration_outbox`、`integration_attempts`。
- [ ] 扩展包裹的补发来源、履约状态、发货时间、物流费用和币种；金额继续使用最小货币单位整数保存。
- [ ] 生成迁移并应用开发库和测试库。

## Task 2: 极风签名、客户端与凭证配置

- [ ] 用官方示例向量先写 HMAC-SHA256 失败测试，验证排序、毫秒时间戳、随机数和十六进制小写签名。
- [ ] 实现 `JifengClient` 端口和 HTTP 适配器：创建、查询、取消订单；超时、响应结构校验、中文错误和脱敏日志。
- [ ] 极风仓库域名、client id/secret、access/refresh token、user id、仓库编号、加拿大邮政渠道 ID 全部从服务端环境变量读取，不进入浏览器或数据库明文日志。
- [ ] token 失效错误可刷新一次并重放原请求；同一 nonce 不重用。

## Task 3: 已付款订单幂等推送极风

- [ ] 领域测试覆盖：仅 `PAID_PENDING_FULFILLMENT` 可推送；每个正常包裹创建稳定 `erpNo`；重复任务不重复创建极风订单。
- [ ] 从加密收件信息构造极风请求；平台固定 `temu`，国家固定 `CA`，物流固定配置的加拿大邮政渠道。
- [ ] 推送成功后包裹进入履约中；部分失败时订单进入 `FULFILLMENT_EXCEPTION` 并保留可重试包裹。
- [ ] pg-boss 周期扫描待推送与可重试记录，指数退避且达到阈值后通知管理员。

## Task 4: 状态同步、Webhook 与发货扣库存

- [ ] 查询轮询和 Webhook 共享同一个状态归并服务；WebHook 验签失败、userId 不匹配或重复事件不改变数据。
- [ ] `status=7` 保存加拿大邮政运单号、发货时间、物流费和币种，并消费该包裹对应的库存锁定。
- [ ] 同一发货事件重复到达不重复扣库存；库存流水保存包裹、订单、极风 ERP 单号和实际 SKU 数量。
- [ ] 全部正常包裹发货后订单进入 `SHIPPED`；异常/获取失败进入 `FULFILLMENT_EXCEPTION`；未全部发货保持 `FULFILLING`。

## Task 5: 补发与极风取消

- [ ] 超级管理员只能对已发货包裹创建补发，必须选择 SKU、数量并填写补发原因。
- [ ] 创建补发时原子锁定货盘库存，生成 `REPLACEMENT` 包裹、明细、审计和稳定补发 `erpNo`。
- [ ] 补发走与普通包裹相同的极风创建/查询流程；仅极风已发货后消费补发锁定库存。
- [ ] 未发货的极风包裹可申请取消；极风确认取消后释放库存，失败则进入可见异常，不伪造本地成功。

## Task 6: 飞书应用客户端、货盘同步与机器人通知

- [ ] 实现飞书 tenant token、知识库节点解析、电子表格范围写入和群消息发送适配器；所有响应做结构校验。
- [ ] 数据库生成固定列货盘快照：序号、SKU、图片、名称、采购价、总库存、可售库存、链接文字、规格、颜色、组合销售、重量、状态。
- [ ] 库存变更进入同步 outbox，1 分钟内增量更新；每天全量覆盖并校验行数和 SKU 集合，失败保留重试与错误详情。
- [ ] 履约异常、补发创建/发货、低库存与补货建议同时在系统通知中心显示并推送内部飞书群；消息不包含收件人明文。

## Task 7: 管理员履约、补发与系统配置 UI

- [ ] 订单详情显示每个包裹的极风状态、ERP 单号、加拿大邮政运单、费用、重试与错误。
- [ ] 提供补发创建、极风重试、取消申请和飞书重新同步操作，均带影响确认、原因和审计。
- [ ] 系统集成页只显示“已配置/未配置”和连接测试结果，不回显任何 secret/token。
- [ ] 桌面和 360/390/430px 手机端均可完成履约异常处理与补发。

## Task 8: 阶段 3 验收

- [ ] 用可控模拟极风服务器验证签名、成功、重复、超时、token 失效、异常、取消和已发货状态。
- [ ] 端到端验证普通包裹与补发都只在极风已发货后扣库存，重复 Webhook 不重复扣减。
- [ ] 用模拟飞书服务器验证表格增量/全量同步、机器人消息脱敏、失败重试和权限错误提示。
- [ ] 运行单元、数据库集成、桌面/手机 E2E、axe、类型检查、lint 和生产构建；更新运行手册和正式凭证清单。

## Phase 3 Definition of Done

- 已付款包裹能幂等进入极风；系统可见待拣货、待发货、已发货、运单、费用和异常。
- 普通发货与补发均只在极风确认已发货后正式扣减库存，重复事件不会重复扣减。
- 飞书货盘由数据库自动同步，飞书不再成为库存真实来源；异常同时出现在系统和内部飞书群。
- 未提供正式凭证时，所有功能可在模拟服务下完整验收；正式域名、应用凭证、仓库和加拿大邮政渠道 ID 配齐后无需改代码即可联调。
