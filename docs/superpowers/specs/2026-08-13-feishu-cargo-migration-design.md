# 飞书货盘结构化迁移与只读镜像设计

日期：2026-08-13
状态：已确认设计，待实施计划
范围：飞书货盘首次迁移、图片资产迁移、结构化数据库接管、独立测试表同步

## 1. 背景与目标

当前约 74 个 SKU 由团队在飞书知识库中的电子表格人工维护，表内包含粘贴图片、商品链接、采购价、库存、规格、颜色、重量和销售状态。极风货盘库存不作为可信来源。

本次工作的目标是：

1. 将现有飞书货盘安全迁移为 PostgreSQL 中的商品、SKU、库存和图片资产。
2. 迁移后以数据库作为商品与库存的唯一真实来源。
3. 保留原业务飞书货盘不变，并将其限制为只读迁移源。
4. 新建独立的“系统货盘测试表”，只展示数据库同步结果。
5. 测试表验收通过后，再由业务负责人单独决定是否切换客户查看入口。

明确不在本阶段执行的事项：

- 不修改、重命名、清空、覆盖、隐藏或调整当前业务货盘。
- 不将人工修改飞书的数据反向同步进数据库。
- 不接入极风货盘库存。
- 不在未经批准的情况下替换客户当前使用的飞书入口。

## 2. 已确认的业务规则

- 当前货盘约有 74 个 SKU，原则上一个 SKU 对应一张粘贴图片。
- 相同“序号”的多行代表同一个商品下的多个 SKU，例如不同颜色或规格。
- 库存为 0、状态为“不可售”的 SKU 也必须迁移并保留，不能删除。
- 人工销售状态独立于库存：人工标记“不可售”时，即使库存大于 0 也不能下单；库存为 0 时无论人工状态如何都不能下单。
- 补货后，只有人工销售状态为“可售”的 SKU 才能恢复可下单。
- “链接文字”是采购/商品链接，必须同时保留显示文字和真实 URL。
- 迁移后的图片由系统接管，保存在服务器独立持久卷中；数据库保存受控的资产引用和校验值。
- 后续所有商品、SKU、库存和图片维护都在系统后台进行。

## 3. 方案选择

采用“源表只读 + 独立测试表 + 数据库接管”的方案。

未采用的方案：

- Excel 中转导入：容易丢失粘贴图片、真实超链接和合并单元格信息。
- 原飞书表与数据库双向同步：会制造两个库存源并产生不可判定的冲突。

## 4. 架构与信任边界

```text
原业务飞书货盘（只读）
  -> 迁移读取器
  -> 字段归一化与图片下载
  -> 预检报告
  -> 管理员确认
  -> PostgreSQL 商品 / SKU / 库存 / 迁移记录 / 审计日志
  -> 图片持久卷
  -> 飞书同步队列
  -> 独立“系统货盘测试表”
```

核心信任边界：

- 原业务货盘只允许进入读取模块。
- 测试表只允许进入写入模块。
- 写入模块必须拒绝源 token，且源 token 与目标 token 相同时启动失败。
- 飞书测试表是展示镜像，不是数据库输入。
- PostgreSQL 是迁移完成后的唯一业务数据源。

## 5. 飞书配置与最小权限

使用企业自建应用“同舟行跨境货盘同步”，机器人能力已启用并发布。

应用身份仅使用以下权限：

- `wiki:node:read`：解析知识库节点。
- `sheets:spreadsheet`：读取源表并写入独立测试表。
- `docs:document.media:download`：下载电子表格中的图片素材。
- `im:message:send_as_bot`：后续发送库存预警和补货通知。

原货盘已将应用添加为协作者。实施时应尽量将原货盘协作权限降为可阅读；无论飞书侧权限为何，代码仍执行源 token 写保护。

建议环境变量：

- `FEISHU_APP_ID`
- `FEISHU_APP_SECRET`
- `FEISHU_CARGO_SOURCE_WIKI_TOKEN`
- `FEISHU_CARGO_SOURCE_SHEET_ID`（可选，未填时必须在预检中明确选择）
- `FEISHU_CARGO_TARGET_SPREADSHEET_TOKEN`
- `FEISHU_CARGO_TARGET_SHEET_ID`
- `FEISHU_INTERNAL_CHAT_ID`（消息通知启用后再配置）

`App Secret` 只进入服务器密钥环境，不进入源代码、数据库、日志、截图或聊天记录。

## 6. 数据模型与字段映射

现有数据表 `products`、`skus`、`inventory_balances`、`inventory_movements` 和 `audit_logs` 可继续使用。需要新增迁移运行/预检记录和图片资产管理所需的数据结构。

字段映射：

| 飞书字段 | 系统字段或规则 |
| --- | --- |
| 序号 | 商品分组键；相同序号建立一个商品 |
| SKU | `skus.sku_code`，全局唯一且必填 |
| 图片 | 读取 `fileToken`、下载、校验并保存到图片持久卷 |
| 名称 | `products.name`，同时用于 SKU 默认名称的组成 |
| 采购价 | 转为人民币分，写入 `skus.default_unit_price_fen` |
| 总库存 | `inventory_balances.total_quantity` |
| 链接文字 | 显示文字与真实 URL 分开提取；URL 写入 `skus.product_url` |
| 规格 | `skus.specification` |
| 颜色 | `skus.color` |
| 组合销售 | `skus.combination` |
| 重量 | 解析并统一转换为 `skus.weight_grams` |
| 状态 | 映射到 `SELLABLE` / `NOT_SELLABLE` |

合并单元格规则：

- 商品级字段允许在同一商品分组内向下继承，包括序号、名称和共用图片。
- SKU 级字段禁止盲目继承，包括 SKU、颜色、库存和明确的销售状态。
- 规格、组合销售、价格、链接和重量仅在确认属于商品级共用字段时继承；解析器必须在预检中展示继承来源。
- 无法判断的数据不猜测，进入阻断错误。

图片规则：

- 支持飞书单元格图片；读取范围获得 `fileToken` 后调用素材下载接口。
- 若实际发现浮动图片，则按锚定行/列解析；无法可靠对应 SKU 时阻断导入。
- 接受格式和大小必须使用白名单；实际 MIME 与文件内容均需校验。
- 文件名不使用用户提供的路径；通过内容摘要生成受控文件名。
- 临时文件与正式文件分区；正式资产只通过受控应用路由提供。

## 7. 首次迁移流程

### 7.1 维护窗口

正式迁移安排约 10–20 分钟维护窗口，在此期间暂停人工修改飞书货盘。

### 7.2 只读预检

1. 解析知识库节点并列出工作表。
2. 读取源工作表数据、公式/富文本值、超链接和图片 token。
3. 归一化商品分组和 SKU 行。
4. 将图片下载到临时目录并计算摘要。
5. 生成预检结果，不写业务表。

预检展示：

- 源文档、工作表、读取时间和源版本/修订号。
- 预计商品数、SKU 数、图片数和总库存。
- 每个 SKU 的最终字段值及继承来源。
- 阻断错误、可重试错误和警告。
- 源内容摘要与图片摘要。

阻断条件至少包括：

- SKU 缺失或重复。
- 价格无法解析或为负数。
- 库存不是非负整数。
- 商品分组无法判断。
- 图片无法与 SKU/商品可靠对应。
- 链接只有显示文字但没有有效 URL。
- 重量单位或销售状态无法识别。

图片临时下载失败允许重试，但未完成图片校验时不得正式导入。

### 7.3 确认与正式导入

- 正式导入前重新读取源版本/修订号和内容摘要。
- 若源表在预检后有任何变化，预检失效，必须重新执行。
- 只有超级管理员可以确认首次导入。
- 首次导入仅在系统 SKU 数量为 0 且不存在成功迁移记录时允许执行。
- 通过单一数据库事务写入商品、SKU、库存余额、初始库存流水、迁移记录和审计日志。
- 初始库存流水使用明确的迁移类型或受控的手工增加语义，原因包含迁移运行 ID。
- 数据库事务成功后才将临时图片原子移动为正式资产；文件落盘失败必须进入可恢复状态，不能伪装成功。
- 成功后永久关闭首次迁移入口，后续变化走系统后台正常维护流程。

## 8. 原业务表保护与独立测试表

### 8.1 原业务表

实施和验收阶段不得：

- 写入任何单元格。
- 新增、删除、移动或重命名工作表。
- 修改格式、筛选、保护、图片或合并单元格。
- 将其作为自动同步目标。

系统应在集成页面醒目标注“原业务货盘受保护，禁止写入”。

### 8.2 独立测试表

由业务负责人创建独立空白电子表格，并将应用添加为可编辑协作者。

测试表结构：

- 每个 SKU 独立一行。
- 表头冻结并支持筛选。
- 不使用合并单元格。
- 同一商品的 SKU 相邻排列。
- 展示图片、商品、SKU、统一拿货价、总库存、可售库存、链接、规格、颜色、组合销售、重量和状态。

测试表完全由数据库生成。被人工修改后，下一次同步以数据库内容覆盖；人工修改不进入数据库，并记录同步异常。

## 9. 日常维护与同步

- 管理员通过系统后台增删改查商品和 SKU，上传/替换图片，维护价格、链接、规格、颜色、重量和人工销售状态。
- 库存调整必须填写原因，记录操作人、时间、调整前后数量和引用。
- 可售库存 = 总库存 − 有效订单锁定。
- 人工不可售优先；库存为 0 时自动不可下单。
- 商品和库存变更通过既有 outbox/worker 模式异步同步测试表。
- 同步失败自动退避重试，不阻塞订单和库存事务。
- 同步状态页面展示源连接、目标连接、最近预检、最近导入、最近同步、行数、失败原因和手动重试入口。

## 10. 异常处理与可恢复性

- 飞书限流、超时和 5xx：指数退避重试，达到上限后进入人工重试队列。
- 权限不足、token 错误和节点类型错误：立即停止，显示明确中文原因，不进行无意义重试。
- 源与目标 token 相同：配置启动失败，禁止任何写入。
- 导入事务失败：数据库整体回滚，预检记录保留失败原因。
- 图片下载或校验失败：保留预检状态，不创建缺图业务 SKU。
- 图片已下载但数据库失败：清理临时文件。
- 数据库成功但正式文件移动异常：迁移标记为需要恢复，禁止对外宣布完成，并提供幂等恢复操作。
- 测试表同步失败：不影响数据库；后续从数据库全量重建目标表。

## 11. 安全与运维

- 图片使用独立 Docker 持久卷，不与数据库数据卷混用。
- 图片上传与迁移均限制 MIME、扩展名、单文件大小、像素上限和总容量。
- 资源访问使用受控路由和不可预测标识，防止路径遍历和任意文件读取。
- 飞书返回体和错误日志不得记录 access token、App Secret、完整图片 token 或敏感 URL 参数。
- 迁移、确认导入、同步和重试全部写审计日志。
- 数据库和图片卷都纳入备份与恢复演练。

## 12. 测试策略

### 单元测试

- 表头识别与字段归一化。
- 合并单元格继承边界。
- 多 SKU 商品分组。
- 金额、库存、重量、状态和超链接解析。
- 单元格图片与浮动图片关联。
- 源 token 写保护和源/目标相同配置拒绝。

### 集成测试

- 飞书 API 鉴权、知识库解析、工作表读取、图片下载和目标写入的模拟契约。
- 74 SKU 规模的完整预检。
- 重复 SKU、负库存、非法价格、图片丢失和链接缺失。
- 源修订号变化导致确认失效。
- 首次导入事务回滚和幂等保护。
- 图片临时区到正式区的恢复路径。
- outbox 重试和从数据库全量重建测试表。

### 端到端验收

- 预计 74 个 SKU 全部导入。
- 74 张图片均可在系统打开。
- 商品分组、价格、库存、链接、重量、规格、颜色和状态抽样对照正确。
- 原业务货盘内容、结构和修订状态未被系统修改。
- 独立测试表与数据库结果一致。
- 桌面端与手机端均能浏览货盘。

## 13. 切换与回退

- 测试表验收完成前，客户仍使用原业务货盘。
- 验收通过后，由业务负责人单独批准切换客户查看入口。
- 切换不要求删除原货盘；原货盘作为迁移前历史依据只读保留。
- 若系统展示或同步出现问题，可临时恢复原入口，但迁移后的库存维护仍以数据库为准，避免重新形成双写。

## 14. 完成标准

本阶段完成需同时满足：

1. 原业务货盘从未被程序写入。
2. 首次迁移预检和确认流程具备审计与幂等保护。
3. 商品、SKU、图片、库存和销售状态完整进入结构化数据库。
4. 系统成为唯一维护入口。
5. 独立测试表能够由数据库稳定重建并同步。
6. 所有关键异常均有中文提示、可追踪记录和安全恢复路径。
7. 业务负责人完成独立测试表验收；客户入口切换仍由后续单独批准。
