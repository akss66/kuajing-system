# 飞书货盘价格占位导入设计

日期：2026-08-15
状态：待用户最终确认

## 背景与目标

飞书源表保持严格只读。当前 `TZX-076` 的“货品价格”为空，但业务决定先在同舟行系统数据库中使用 `¥99.00` 作为临时占位价格，以便完成 76 个产品编号、140 个完整 SKU 的分组与字段回填。

本设计只解决这一项明确占位，不允许把所有空价格自动替换为 99，也不修改飞书源表。

## 方案

采用一次性、显式、可审计的 SKU 级覆盖参数：

```text
--cargo-price-placeholder=TZX-076:99.00
```

预检和正式回填必须使用相同参数。没有该参数时，现有严格解析规则保持不变，`TZX-076` 仍因缺少货品价格而阻止迁移。

## 边界与安全规则

1. 覆盖仅作用于系统数据库写入，不调用任何飞书写接口。
2. 覆盖只在目标 SKU 的源单元格为空时生效；若源表已有合法价格或包含非空非法文本，则拒绝执行，避免掩盖新数据。
3. 参数必须包含规范 SKU 与两位小数人民币金额。本次允许值为 `TZX-076:99.00`。
4. 其他 SKU 缺价仍产生阻塞错误，不能共享或继承本占位值。
5. 预检必须输出占位 SKU、占位金额和占位数量，并继续验证：
   - 产品编号数量为 76；
   - SKU 数量为 140；
   - 数据库 SKU 集合与飞书完整 SKU 集合完全一致；
   - 无其他阻塞问题。
6. 正式回填继续使用数据库事务与 advisory lock；任一校验失败时整体回滚。

## 代码边界

- `cargo-parser` 增加可选的 SKU 价格覆盖输入。默认不传时行为完全不变。
- 解析器在空价格且存在精确覆盖时生成 `CARGO_PRICE_PLACEHOLDER_APPLIED` 警告，并将 `99.00` 转为内部 `99000 milli-yuan`。
- `catalog-field-refresh` 将覆盖信息同时用于 preview/apply，并把实际使用的覆盖项纳入返回值和审计日志 `afterJson`。
- 运维 CLI 增加显式参数解析；preview 与 apply 共用同一参数结构。
- 不新增数据库表或迁移，不更改普通页面的信息架构。

## 数据流

1. 只读读取飞书源表。
2. 解析每一行并校验“飞书序号 = TZX 中间编号”。
3. 遇到 `TZX-076` 空货品价格时，应用显式 `¥99.00` 系统占位；其他缺失仍阻塞。
4. 生成只读预检结果，确认 76/140、SKU 集合一致和占位明细。
5. 经运维确认后，在单个数据库事务内更新产品分组、货品价格与字段。
6. 写入审计日志，记录操作者、原因、占位 SKU 和金额。

## 错误处理

- 参数格式错误：`INVALID_CARGO_PRICE_PLACEHOLDER`
- 覆盖 SKU 与源表 SKU 不匹配：`CARGO_PRICE_PLACEHOLDER_UNUSED`
- 源价格非空时仍试图覆盖：`CARGO_PRICE_PLACEHOLDER_NOT_NEEDED`
- 其他解析问题：继续使用现有阻塞错误，禁止回填。

## 测试与验收

- 单元测试先证明：无覆盖时缺价仍失败；精确覆盖时只修复 `TZX-076`；覆盖不污染其他行；合法源价格不能被覆盖。
- CLI 测试证明参数格式、金额单位及 preview/apply 一致性。
- 集成测试证明预检得到 76/140，并在 apply 后数据库产品价格为 `99000 milli-yuan`，审计日志包含占位明细。
- 生产先运行只读预检；只有精确返回 76/140、140 个匹配 SKU、0 个阻塞问题后才允许 apply 与版本切换。

## 后续替换

占位价格不是永久真实价格。取得真实值后，通过同一受审计的货盘字段刷新流程替换 `TZX-076` 的系统价格；不反向写入飞书。
