# SKU 全生命周期管理与货品价格统一规格

日期：2026-08-17
状态：待确认

## 1. 目标

把 `/admin/catalog` 从只读核对页升级为运营人员可以长期维护的 SKU 工作区，并使手工维护字段与飞书货盘字段保持一致。客户货盘、订单预览和订单落单统一使用“货品价格”，不再读取或设置客户专属价，也不得把采购价当作客户拿货价。

本规格覆盖：

- 单个 SKU 的创建、查看、编辑和删除；
- 一个商品（来源序号）下包含一个或多个 SKU；
- SKU 批量设置销售状态、移动所属商品和删除；
- 图片、库存和价格的安全维护；
- 客户侧“拿货价”与订单计价统一到货品价格；
- 权限、审计、并发、历史数据和响应式验收。

本规格相关价格规则替代 `2026-08-14-feishu-field-aligned-ui-design.md` 中“客户实际拿货价继续遵守客户专属价优先级”的旧规则；其余飞书只读、字段映射、商品分组和库存追溯规则继续有效。

## 2. 核心业务模型

### 2.1 商品与 SKU

- `products` 表示飞书“序号”对应的商品父级。
- `skus` 表示商品下可交易的规格变体。
- 同一个 `sourceSequence` 只能对应一个商品；一个商品可包含多个 SKU。
- `TZX-016-1`、`TZX-016-2` 等 SKU 应归属序号 `16`；手工创建和编辑时服务端校验 TZX 编码中的父编号与商品来源序号一致。
- 非 TZX 编码不依赖编码推导分组，但仍必须显式选择商品。

### 2.2 飞书字段映射

| 界面字段 | 数据归属 | 数据库字段 | 约束 |
|---|---|---|---|
| 序号 | 商品 | `products.sourceSequence` | 必填、唯一，数字文本规范化后保存 |
| SKU | SKU | `skus.skuCode` | 必填、全局唯一 |
| 图片 | SKU | `skus.imageAssetId` / `imageUrl` | 每 SKU 最多一张；JPEG/PNG/WebP；复用受保护资产存储 |
| 名称 | 商品 | `products.name` | 同组 SKU 共享 |
| 采购价 | SKU | `skus.defaultUnitPriceMilliYuan` | 管理员内部成本/采购事实，非客户拿货价 |
| 总库存（份） | SKU 库存 | `inventory_balances.totalQuantity` | 创建时可录入初始库存；后续只能走库存调整/盘点 |
| 链接文字 | 商品 | `products.linkText` | 同组 SKU 共享 |
| 链接地址 | SKU | `skus.productUrl` | 仅允许 `http` / `https` |
| 规格 | SKU | `skus.specification` | 可空，但界面明确提示未提供 |
| 颜色 | SKU | `skus.color` | 可空 |
| 组合销售 | SKU | `skus.combination` | 可空 |
| 重量 | SKU | `skus.weightGrams` | 非负整数克 |
| 状态 | SKU | `skus.saleStatus` | `SELLABLE` / `NOT_SELLABLE` |
| 货品价格 | 商品 | `products.cargoUnitPriceMilliYuan` | 客户拿货价与订单计价的唯一目录价格 |

金额继续使用整数毫元保存，禁止 JavaScript 浮点金额入库。货品价格为商品级字段，修改后影响该商品下全部 SKU；界面必须在提交前明确提示影响范围。

## 3. 管理员工作区

### 3.1 信息架构

`/admin/catalog` 保留“商品与 SKU”主标题，首屏提供三个明确入口：

1. `新建 SKU`：创建新商品及首个 SKU，或向已有商品添加 SKU。
2. `批量管理`：选择 SKU 后批量修改。
3. `新增 SKU 映射`：保留现有店铺 SKU 映射能力。

删除 `设置客户价` 入口、抽屉、Server Action 和相关提示。页面说明改为“维护商品、SKU、货品价格和店铺映射”。

桌面表格列：选择、序号、商品、SKU、规格/属性、采购价、总库存、可售库存、货品价格、状态、SKU 链接、操作。原“来源商品”统一改为“商品”。每个 SKU 行提供 `管理` 按钮；移动端在 SKU 变体卡中提供相同入口。关键触控目标不小于 44px。

### 3.2 新建 SKU

新建抽屉第一步选择：

- `添加到已有商品`：搜索并选择商品，显示其序号、名称、链接文字和货品价格；这些共享字段不在本步骤重复编辑。
- `创建新商品`：填写序号、名称、链接文字和货品价格，再填写首个 SKU。

SKU 区完整填写：SKU 编码、图片、采购价、初始库存、链接地址、规格、颜色、组合销售、重量、销售状态。除规格/颜色/组合销售/链接文字/链接地址/图片外，其余字段必填。新商品的货品价格必填且不得为负。

创建操作在一个数据库事务内完成：

- 创建或锁定商品；
- 创建 SKU；
- 初始化库存余额；
- 初始库存大于 0 时写入一条 `MANUAL_INCREASE` 库存流水，原因码使用新增的稳定原因 `SKU_INITIAL_STOCK`（展示“SKU 初始库存”）；
- 写入商品/SKU/库存审计；
- 任一步失败全部回滚。

不得通过直接覆盖库存余额的方式制造初始库存，也不得在 SKU 编辑页直接改总库存。

### 3.3 单个管理

`管理 SKU` 抽屉分为三段：

- `商品资料（同组共享）`：序号、商品名称、链接文字、货品价格；保存前显示受影响 SKU 数量。
- `SKU 资料`：图片、SKU、采购价、链接地址、规格、颜色、组合销售、重量、销售状态。
- `危险操作`：删除 SKU，并要求填写操作原因和二次确认。

商品资料与 SKU 资料分别提交，避免修改一个 SKU 属性时误改整组商品。SKU 编码修改后，历史订单继续使用订单快照；现有店铺 SKU 映射继续指向同一个 SKU ID。

### 3.4 批量管理

表格和移动卡片支持逐项选择、当前结果全选和清空选择。一次最多处理 100 个不同 SKU ID。首版提供：

- 批量设为可售；
- 批量设为不可售；
- 批量移动到一个已有商品；
- 批量删除。

批量移动会同时改变 SKU 所属商品，不复制 SKU、图片、库存、映射或历史。若 TZX SKU 编码父编号与目标商品序号不一致，整批拒绝，不允许部分成功。

批量动作必须要求操作原因、显示实际影响数量，并在单个短事务内按 SKU ID 稳定顺序锁定。输入去重、限制数量、校验权限；任何一项失败时整批回滚。审计既写一条批次摘要，也写可按 SKU 查询的明细。

## 4. 删除与历史数据

用户界面统一使用“删除 SKU”，服务端根据引用自动选择安全执行方式：

### 4.1 可物理删除

仅当 SKU 同时满足以下条件时物理删除：

- 总库存为 0；
- 没有库存流水和库存预留；
- 没有订单行和已解析导入行；
- 没有其他业务表引用。

可清理的配置型引用（未使用的店铺别名、已停用的旧客户价配置、零库存余额）在同一事务内先删除。若商品删除最后一个 SKU，且商品没有其他业务引用，则同时删除空商品。图片资产采用引用计数/查询判断；仍被其他 SKU 使用的资产不得删除。

### 4.2 有历史引用

存在任何业务历史时不物理删除，而是设置 SKU 生命周期为 `ARCHIVED`，同时：

- 强制 `saleStatus=NOT_SELLABLE`；
- 关闭 SKU 别名；
- 从客户货盘、新订单、批量草稿解析和管理员默认结果中隐藏；
- 保留订单、库存、审计、图片引用和 SKU 快照。

管理员可通过“已删除”筛选查看归档 SKU，并执行恢复。恢复前重新校验 SKU 编码唯一性、所属商品状态与价格完整性；恢复后默认仍为不可售，必须由管理员显式上架。

删除和恢复均要求原因、二次确认和完整审计。数据库外键继续使用 `restrict`，禁止级联删除订单、库存流水或导入历史。

## 5. 客户拿货价与订单计价

### 5.1 唯一价格来源

客户界面名称由“实际拿货价”改为“拿货价”。该值只读取 `products.cargoUnitPriceMilliYuan`：

- 不读取 `customer_sku_prices`；
- 不回退到 SKU 采购价；
- 不允许目录缺价时按 0 元下单。

客户货盘、批量草稿预览、单店订单预览和最终订单行必须调用同一个货品价格解析服务。订单提交事务内再次锁定/读取商品价格，避免预览后价格变化产生错误结算。订单行继续保存价格快照，因此后续改价不影响历史订单。

### 5.2 缺价状态

商品缺少货品价格时：

- 管理端显示“货品价格待维护”；
- 客户可看见商品和 SKU，但显示“价格待维护”，不可下单；
- 订单预览/提交返回稳定业务错误，不得回退采购价或 0 元。

### 5.3 旧客户价数据

首轮上线不物理删除 `customer_sku_prices` 表或历史行，以便审计和回滚；所有生产读取、写入入口立即停用。迁移将现有活动记录统一置为 `active=false`，并写入系统审计摘要。后续确认无需回滚后，另行设计物理清理，不与本次上线绑定。

## 6. 权限、安全与并发

- 所有商品/SKU/批量动作仅允许已启用管理员；客户请求直接拒绝。
- Server Action 只接收标量、受限枚举、UUID 和受控文件；不信任客户端的价格、库存、影响数量或归档判定。
- 图片沿用受保护目录、内容哈希去重、MIME/像素/大小校验；禁止任意路径和 SVG/脚本上传。
- URL 仅允许绝对 `http` / `https`；展示使用安全外链属性。
- 删除、恢复、移动、改价、改状态、创建初始库存都必须记录 actor、before/after、结构化动作和人工原因。
- 商品与 SKU 更新采用数据库行锁；锁顺序为商品 ID 后 SKU ID 升序。唯一约束冲突返回可理解的字段错误，不泄漏 SQL/路径/密钥。
- 飞书继续只读；本功能只写系统 PostgreSQL 与系统资产目录，不调用飞书写接口。

## 7. 数据库与模块边界

### 7.1 迁移

新增 SKU 生命周期字段：

- `skus.lifecycle_status`: `ACTIVE | ARCHIVED`，默认 `ACTIVE`；
- `skus.archived_at`: 可空时间；
- `skus.archived_by_admin_user_id`: 可空管理员 ID/文本引用；
- `skus.archive_reason`: 可空文本；
- 为默认活跃查询和归档列表增加必要索引；
- 库存原因枚举增加 `SKU_INITIAL_STOCK`。

迁移必须先兼容旧代码再切换读取，且支持从当前生产空闲状态执行。不得重写历史订单或库存流水。

### 7.2 代码结构

- `src/modules/catalog/sku-management-service.ts`：单 SKU 创建、商品/SKU 编辑、删除/恢复、批量动作；不把业务事务留在 Server Action。
- `src/modules/catalog/pricing.ts`：唯一货品价格解析；移除客户价覆盖和采购价回退。
- `src/modules/catalog/admin-catalog.ts`：活跃/归档筛选与完整管理 DTO。
- `src/modules/catalog/customer-catalog.ts`：客户安全 DTO，不包含采购价、来源序号或归档字段；价格来自商品货品价格。
- `src/modules/catalog/actions.ts`：鉴权、Zod 解析、调用服务、稳定错误映射和 revalidate。
- `src/components/catalog/*`：工作区、选择状态、管理抽屉、图片上传与移动端卡片；组件不直接访问数据库。
- `src/modules/inventory/service.ts`：复用锁定余额与流水能力完成初始库存，不新增绕过流水的库存写路径。

## 8. 代码风格与接口约束

- TypeScript 严格类型；货币、库存、重量均使用安全整数。
- Zod 仅用于输入边界；核心服务再次验证跨字段业务不变量。
- 领域错误使用稳定错误码，Server Action 映射为中文消息。
- 服务输入使用显式对象；批量接口只返回成功数量、执行模式（物理删除/归档）和安全摘要，不返回底层数据库错误。
- 查询默认显式过滤 `ACTIVE`，不得依赖 UI 隐藏归档数据。
- 不引入新的大型组件库；复用现有 Button、Drawer、Table、Badge、ActionForm 和资产存储。

## 11. 非目标与边界

- 不改飞书业务表，不向飞书写回。
- 不把采购价展示给客户。
- 不在本次物理删除客户价历史表。
- 不新增批量改库存；库存批量盘点继续由库存模块负责。

## 12. 完成标准

- 运营人员无需寻找隐藏入口，即可从每个 SKU 行完成管理。
- 新建 SKU 能录入飞书字段对应的全部系统字段，并正确加入商品分组。
- 管理员可安全批量上/下架、移动和删除 SKU。
- 历史 SKU 可在 UI 中删除；无引用时物理删除，有历史时归档且历史完整可追溯。
- 系统不再允许设置客户价，旧客户价不再影响任何展示或新订单。
- 客户“拿货价”、订单预览和订单行均使用货品价格；采购价永不作为回退。
- 所有新增危险操作有权限、原因、审计、事务和并发保护。
- 全量 unit/integration/E2E/typecheck/lint/build/diff-check 通过后才允许部署。

## 13. 已确认决策与开放问题

已确认：

- 历史 SKU 在界面中允许删除；底层按是否存在业务历史自动选择物理删除或归档删除。
- 系统必须具备批量管理能力，首版范围为销售状态、移动商品和删除。
- 取消设置客户价。
- 客户“拿货价”对应货品价格，而不是采购价。
- 商品列表列名使用“商品”，不使用“来源商品”。

开放问题：无。规格批准后可直接进入实施。
