# 同舟行商家工作台侧栏与按钮体系设计

日期：2026-08-16
状态：待用户复核
适用范围：管理员后台与客户门户共用的商家工作台外壳、侧栏导航和按钮视觉体系

## 1. 背景与问题

当前商家工作台的业务信息架构已经稳定，但视觉表达存在三个明显问题：

1. 侧栏分组标题被绘制成带边框、圆角和下拉箭头的控件，视觉上更像一组表单选择器，而不是导航层级。分组标题反而比当前页面更重，削弱了定位效率。
2. 深色顶栏的品牌区使用半透明白色右边框，浅色侧栏又使用中性灰右边框，两种边界在顶栏与侧栏交界处形成明显白线和断点。
3. 共享主按钮使用较亮的青绿色、轻投影和按下位移，接近通用组件库默认样式，缺少成熟运营后台应有的稳定感；系统内不同动作的优先级也不够清楚。

本次整改不改变业务路由、菜单分组、权限、文案语义或页面功能，只重构商家工作台外壳的视觉层级与共享动作语言。

## 2. 设计目标

- 让管理员在一眼内先看到当前页面，再理解它所属的业务分组。
- 保持中等偏紧凑的信息密度，不用大圆角、重阴影或宽侧栏制造所谓高级感。
- 让深色顶栏成为连续、完整的全局层，消除侧栏交界处白线。
- 用一套明确的按钮层级覆盖页面主操作、次操作、低优先级操作和危险操作。
- 复用现有 shadcn、Radix、Tailwind 与同舟行设计令牌，不引入新的运行时组件库。
- 管理员桌面端保持高效率，客户门户和移动端关键操作满足至少 44px 触控目标。

## 3. 技术选型

项目已经包含 `src/components/ui/sidebar.tsx`，它是官方 shadcn Sidebar 结构原语的本地副本，具备 Provider、Group、GroupLabel、Menu、MenuButton、移动 Sheet 与折叠状态等能力。

本次采用以下边界：

- 使用现有 shadcn Sidebar 原语重组壳层结构，不新增依赖。
- 不直接套用 shadcn 官方主题、默认宽度或示例信息架构。
- 不引入 Base UI、React Aria 或 Ark UI 替换现有 Radix 交互原语。
- Origin UI 只作为按钮组合和间距参考，不覆盖项目的 `components/ui` 或 CSS 变量。
- Tremor 只保留为未来报表图表候选，不参与本次侧栏与按钮整改。

## 4. 侧栏方案

### 4.1 桌面端：标签式分组

桌面端采用静态分组标签，不再把每个分组标题绘制成可折叠的边框按钮。

- “运营总览”作为直接导航项，不再放在只有一个子项的“工作台”折叠组中。
- “客户与货品”“订单履约”“资金与数据”“系统管理”显示为静态分组标签。
- 分组标签使用 12px 中文产品字体、中等字重、零额外字距和克制的灰色。
- 分组之间用 18–22px 垂直间距建立层级，不使用独立边框盒子。
- 导航项保持 40px 高，图标 18px，文字 14px。
- 当前页面同时使用以下非颜色单一提示：
  - 左侧 2px 深海青绿短轨；
  - 很浅的青绿色背景；
  - 更深的文字与图标颜色；
  - `aria-current="page"` 语义保持不变。
- 侧栏宽度继续使用现有约 224px，不直接采用 shadcn 默认 256px，避免占用数据工作区。
- 桌面端不折叠单个业务分组；如需节省空间，只允许整个侧栏收起为图标栏，并使用官方 Sidebar 的整体折叠机制。

### 4.2 移动端：扁平折叠分组

移动端继续通过左侧 Sheet 展示导航，但分组标题改为无边框的扁平折叠行。

- 分组触发器最小高度 44px，保留清楚的展开/收起箭头。
- 当前页面所在分组默认展开，其余分组可折叠。
- 导航项最小高度 44px。
- 关闭抽屉后焦点返回导航触发按钮。
- 不采用复杂 `tree` 角色或自定义方向键模型；继续使用按钮、列表和链接的原生语义。

### 4.3 信息架构保持

保留现有业务分组与权限过滤：

- 运营总览
- 客户与货品
- 订单履约
- 资金与数据
- 系统管理

普通管理员仍不显示超级管理员专属入口；客户门户继续使用自己的导航条目，但共享同一层级语言。

## 5. 顶栏与侧栏接缝

白线不是浏览器渲染故障，而是两套边框在壳层交界处叠加造成的视觉断裂。

整改规则：

- 移除深色品牌区右侧的 `border-white/12`。
- 深色顶栏在桌面宽度内保持连续的单一背景，不在品牌区与工具区之间增加竖向分隔线。
- 顶栏只保留一条统一的底部边界。
- 浅色侧栏从顶栏下方开始，只保留一条中性灰右边框。
- 侧栏宽度、顶栏品牌宽度和内容区左偏移必须由同一个 CSS 变量控制，禁止三个位置分别写数值。
- 不通过覆盖白色、负边距或伪元素遮挡白线；从网格和边框所有权上消除根因。

## 6. 全局按钮体系

按钮继续使用项目内 `Button` 组件，但重构视觉令牌与动作层级。

### 6.1 Primary：页面主操作

适用于“新建客户”“提交订单”“保存客户资料”等当前上下文中唯一的主要动作。

- 默认背景：深海青绿，目标颜色约 `#146F64`。
- Hover：轻微变深，约 `#0E5F56`。
- Pressed：继续变深或改变边框，不做垂直位移。
- 白色文字，必须达到 WCAG AA 对比度。
- 无投影；允许一条与背景同色的实体边框。
- 高度：桌面页面 CTA 40px；客户移动端和移动关键操作至少 44px。
- 圆角：8px。
- 图标：Lucide 16px，图标与文字间距 8px；不使用文本字符模拟加号。
- 每个页面标题区最多一个 Primary。

### 6.2 Secondary：次操作

适用于“导出数据”“刷新”“取消”等不会与主操作竞争的动作。

- 白色或背景色表面。
- 中性灰边框与深色文字。
- 无投影。
- Hover 只使用轻微中性灰底色。

### 6.3 Ghost：低优先级操作

适用于表格行内“查看详情”、工具栏辅助动作和不需要容器强调的操作。

- 默认透明背景和透明边框。
- Hover 使用轻微中性背景。
- 不得与 Primary 同时表现为实色按钮。

### 6.4 Destructive：危险操作

适用于“停用客户”“断开连接”“删除”等需要明确风险提示的操作。

- 页面内默认使用白底、红色文字和浅红边框，避免大面积粉红色填充。
- 只有确认对话框中的最终不可逆动作可使用红色实底。
- 危险按钮不能只靠红色表达，必须使用明确动作文本。

### 6.5 共享状态

所有按钮变体必须统一支持：

- 清晰、可见且不被裁切的键盘焦点环；
- 禁用状态下仍可辨认的文字对比度；
- 加载状态保持按钮宽度稳定，图标位置显示旋转指示；
- 加载期间禁止重复提交；
- `prefers-reduced-motion` 下取消非必要过渡；
- 图标按钮使用可访问名称；
- 链接行为继续使用链接语义，不用 Button 强制模拟。

## 7. 组件与文件边界

预计实现聚焦以下共享边界：

- `src/components/layout/merchant-shell-frame.tsx`
- `src/components/layout/admin-shell.tsx`
- 客户门户对应的 shell 组装文件
- `src/components/layout/navigation-section.tsx`，或以 shadcn Sidebar 原语替换其桌面职责
- `src/components/ui/sidebar.tsx`
- `src/components/ui/button.tsx`
- `src/app/globals.css`
- 相关 unit、E2E 和视觉快照

页面业务组件不应逐页覆盖按钮颜色、阴影或圆角。确有特殊布局时，只允许设置排列、宽度和响应式尺寸，不允许重新定义视觉层级。

## 8. 响应式与可访问性

- 桌面验收宽度：1440×900、1920×1080。
- 移动验收宽度：430×900、390×844、360×800。
- 桌面导航、移动抽屉和按钮必须支持键盘完整操作。
- 页面当前项必须有颜色以外的可识别提示。
- 关键移动按钮触控区至少 44×44px。
- 所有文本和状态达到 WCAG 2.2 AA。
- 200% 浏览器缩放下，导航与页面标题不发生横向溢出或遮挡。

## 9. 验收标准

### 9.1 视觉

- 侧栏不再出现像输入框或 Select 的分组标题。
- 当前页面视觉权重大于所属分组标签。
- 顶栏品牌区和工具区之间不存在白色竖线。
- 侧栏与工作区之间只有一条连续的中性分界线。
- “新建客户”等主按钮无投影、无按下跳动，和次操作形成清楚层级。
- 管理员与客户页面使用同一按钮语言。

### 9.2 行为

- 所有现有菜单路由、权限过滤和 `aria-current` 行为保持不变。
- 移动导航可以打开、折叠、选择并正确关闭。
- 整体侧栏折叠状态在刷新后按现有产品决定保持或恢复；不得出现服务端/客户端 hydration 不一致。
- 按钮加载和禁用状态不重复提交。

### 9.3 自动化验证

- 共享侧栏和按钮 unit tests 覆盖当前项、权限过滤、移动折叠、按钮变体与加载状态。
- E2E 覆盖管理员和客户的桌面/移动导航、焦点返回、44px 触控目标、无横向溢出和无 hydration/page/console 错误。
- axe serious/critical 为 0。
- 受影响的无 mask 视觉快照逐张人工复核后更新。
- `typecheck`、`lint`、完整 unit 和相关 E2E 全部通过。

## 10. 非目标

- 不更改菜单名称、路由、角色权限或业务流程。
- 不把后台改成深色主题。
- 不引入新图标库或新的运行时 UI 框架。
- 不重做页面表格、表单、卡片或报表内容。
- 不为了视觉效果增加大面积空白、动画或装饰性渐变。

## 11. 推荐实施顺序

1. 为现有壳层和按钮行为补充 RED 测试与视觉基线证据。
2. 使用现有 `sidebar.tsx` 原语重组桌面/移动侧栏，保持路由与权限数据源不变。
3. 消除顶栏/侧栏接缝并统一宽度变量。
4. 重构共享 Button 视觉与状态，逐页清除会破坏新体系的局部覆盖。
5. 同时验证管理员和客户门户的桌面/移动矩阵。
