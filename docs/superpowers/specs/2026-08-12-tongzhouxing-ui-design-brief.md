# 同舟行跨境 UI 设计简报

状态：全系统商家中心视觉方向已确认通过，等待书面规范复核。

## 1. Feature Summary

为同舟行跨境的超级管理员后台和客户门户建立同一套生产级、高保真、响应式产品界面。界面服务于订单、库存、客户、资金、补发和异常处理等高频任务，第一期只提供浅色主题。

管理员以桌面端为主，要求一屏处理较多数据；客户同时使用手机和电脑，上传订单、付款和查看物流必须在小屏上完整可用。

## 2. Primary User Action

用户进入任意页面后，应立即知道当前最需要处理的任务、相关业务状态和下一步操作。

- 管理员的核心动作是发现异常并快速处理，而不是逐页寻找问题。
- 客户的核心动作是选择店铺、上传订单、确认金额并跟踪付款或发货状态。

## 3. Design Direction

### 视觉策略

全系统采用已经批准的“同舟行商家工作台”方向。TikTok Shop 商家中心只作为 UI 美学和组件质感参考，不作为信息架构、栏目、业务命名、角色权限或操作流程参考。

桌面端使用深炭黑全宽工具顶栏、浅色左侧导航、浅冷灰工作画布和白色业务面板。顶栏提供品牌、帮助、消息、通知和当前账号等全局工具；左侧导航继续呈现同舟行自己的业务模块。整体强调成熟商家后台的稳定、克制和高密度，而不是通用 SaaS 模板的圆润卡片感。

采用 Restrained 色彩策略：深海青绿只用于主操作、链接、键盘焦点、信息状态和少量强调；Logo 红只属于品牌标志，不用于主按钮或导航选中。深炭黑只用于顶栏和选中导航等有限区域，不扩展为深色主题或黑色数据大屏。

场景定义为“白天办公室里的跨境商家工作台”：光线充足、数据可信、状态清楚、操作迅速。

### 参考来源

- TikTok Shop 商家中心：仅参考顶栏气质、侧栏密度、内容留白、表格层级和商家后台组件美学。
- shadcn/ui：开放、可定制和无障碍的组件基础。
- Next Shadcn Dashboard Starter：Next.js 后台框架、筛选表格、表单和错误状态模式。
- Saleor Dashboard：商品、SKU、库存和订单详情的信息组织。
- 飞书：中文表格、表单和操作反馈的熟悉感。

### 方向选择结果

采用视觉探针 B“同舟行商家工作台”的修正版：

- 保留同舟行现有管理员后台和客户门户的信息结构。
- 管理员后台继续使用运营总览、客户与店铺、商品与 SKU、货盘库存、订单管理、补发管理、收款与余额、报表分析、系统通知、外部集成、系统健康和审计日志等既定模块。
- 客户门户继续使用工作台、货盘选品、批量拿货、单店上传、我的订单、待付款、余额与流水和店铺数据等既定模块。
- 批量拿货的新页面、状态与结算能力按照已批准的多店铺批量拿货规范加入，不为模仿参考产品而重新分组。
- 只更新全局外壳、排版、颜色、间距、表格、表单、状态标签、抽屉和反馈组件的视觉表达。
- 不复制 TikTok Shop 的 Logo、栏目顺序、市场、广告、联盟、直播、成长中心、应用或财务等业务模型。

### 信息架构冻结规则

视觉改造不得擅自改变以下内容：

- 路由、角色权限、客户数据隔离和超级管理员权限边界。
- 已确认的菜单模块、页面名称和页面之间的业务关系。
- TEMU Excel 上传、库存锁定、余额结算、线下核款、极风履约和飞书同步流程。
- 页面中的必要字段、状态、批量操作和错误恢复入口。

如果某项视觉调整会导致信息被隐藏、操作被合并或流程层级发生变化，必须按产品功能变更重新确认，不能作为“UI 优化”直接实施。

## 4. Scope

- Fidelity：生产级高保真，不交付临时后台模板。
- Breadth：完整管理员后台和客户门户的统一设计系统，以及第一阶段所有真实页面。
- Interactivity：最终实现为可真实操作的响应式组件，不是静态图片。
- Time intent：按功能阶段交付，但每阶段页面达到可上线质量后才进入下一阶段。
- Theme：只做浅色主题。
- Accessibility：WCAG 2.2 AA、键盘可达、可见焦点、减少动画模式。

## 5. Layout Strategy

### 全站框架

- 桌面端顶部使用约 48–52px 高的深炭黑工具栏，左侧展示正式 Logo、“同舟行跨境”和当前端名称，右侧展示帮助、消息、通知和账号入口。
- 顶栏不承载具体业务模块导航，不把业务栏目改造成 TikTok Shop 的结构。
- 左侧使用约 208–224px 的浅色固定导航；关键模块名称默认可见，不依赖只看图标猜功能。
- 导航选中项采用深炭黑底与白色文字，悬停使用浅灰背景；深海青绿只作为焦点、徽标或细节强调。
- 内容画布使用浅冷灰背景，最大内容宽度按业务页面控制；页面标题区包含面包屑、标题、说明和最多一个主操作。
- 页面主体优先使用白色面板、细边框、分隔线和紧凑间距，不把所有内容包装成漂浮卡片。
- 静态面板使用 4–8px 小圆角，阴影只用于菜单、抽屉、对话框和真正脱离画布的浮层。

### 排版与数据密度

- 中文使用系统无衬线字体，英文和数字优先使用 Inter；金额、库存、日期和编号启用等宽数字。
- 桌面页标题约 24px，区域标题 15–18px，正文和表格以 13–14px 为主，辅助文字不低于 12px。
- 统计信息优先使用一条连续指标带或紧凑分区，减少四处漂浮的大号指标卡。
- 表格行高以 40–48px 为主，表头背景使用极浅灰；金额和数量右对齐，操作列位置稳定。
- 状态标签使用小圆角、低饱和语义底色和明确文字，不能使用大面积高饱和色块。

### 运营总览

- 顶部采用紧凑的关键指标带，不使用夸张大号数字卡片。
- 主要区域展示待处理订单、库存预警和每日排行。
- 异常队列作为右侧上下文区域，集中展示极风失败、待核款、付款超时和紧急补货。

### 数据工作区

- 订单、库存、客户和资金页面使用页签、搜索、组合筛选、批量操作和数据表格。
- 筛选状态写入 URL，刷新或分享页面后仍保持相同工作上下文。
- 关键列固定，金额和数量右对齐并使用等宽数字；状态列保持一致位置。
- 详情优先使用页面内分区或侧边抽屉，只有需要阻断用户决策时才使用模态框。

### 客户门户

- 与管理后台共享颜色、字体和组件状态，但采用更大的触控目标和更宽松的局部间距。
- 客户门户使用相同的深色顶栏和浅色侧栏美学，但只显示客户自己的功能和账号上下文。
- 当前店铺始终清晰可见，上传前必须确认店铺。
- 上传流程使用连续步骤：选择店铺和文件、校验预览、确认金额、付款结果。

### 移动端

- 左侧导航折叠为抽屉，顶部保留当前页面和关键操作。
- 深色顶栏保留品牌识别，但压缩全局工具，只显示菜单、当前页面、通知和账号；不得为了复刻桌面而拥挤排列。
- 关键触控目标不小于 44px；主要正文不小于 14px。
- 表格按任务选择信息分组、主次字段折叠、固定首列或横向滚动，禁止把桌面表格整体缩小。
- 筛选器在手机端进入全宽抽屉，已启用条件在页面上以可移除标签展示。
- 关键提交动作可在流程底部粘性显示，但不能遮挡表格最后一行或系统提示。
- 使用真实手机宽度覆盖 360px、390px、430px 三档验收。

## 6. Key States

每个页面和组件都必须定义以下状态：

- Default：默认数据、当前上下文和主操作清楚可见。
- Loading：使用与真实内容结构一致的骨架，不在页面中央放单一转圈动画。
- Empty：说明为什么为空，并提供唯一合理的下一步动作。
- Error：说明错误原因、未受影响的数据以及重试或修复入口。
- Success：在原操作位置确认成功，并及时刷新余额、库存或状态。
- Disabled：说明为什么不可操作，不只降低透明度。
- Permission denied：客户访问其他客户数据时返回安全页面，不泄露对象是否存在。
- Offline/API degraded：极风或飞书不可用时保留本地业务数据，展示同步状态和重试入口。
- Large data：订单和 SKU 达到数百或数千条时仍保持筛选、分页和滚动性能。

## 7. Interaction Model

- 普通状态变化使用 150–200ms 的快速过渡；不做编排式页面入场动画。
- 按钮具备默认、悬停、焦点、按下、禁用和加载状态，加载时保持宽度稳定。
- 表格行单击进入详情；复选框只负责批量选择，不能与行跳转冲突。
- 危险操作先显示具体影响范围，确认文案包含对象和后果。
- 保存失败时保留用户输入，错误聚焦到首个无效字段。
- 后台长任务以非阻塞状态显示进度，用户可以离开页面后继续查看结果。
- `prefers-reduced-motion` 启用时移除位移和缩放，只保留即时变化或短淡入。

## 8. Content Requirements

- 页面和按钮使用业务语言，如“确认已收款”“释放库存”“重新推送极风”，不用抽象技术词。
- 状态文案在所有页面保持统一，例如“待付款”“待核款”“待推送极风”“待发货”“已发货”。
- 金额统一显示人民币符号和两位小数；数据库仍使用人民币分整数。
- 库存同时明确区分总库存、锁定库存和可售库存。
- 倒计时显示剩余时间并说明超时后果。
- 错误信息需要包含可行动建议，但不能暴露密钥、完整请求或消费者隐私。
- 正式 Logo 来源为 `C:\Users\AKSSINA\Desktop\同舟行logo.png`，保留透明背景和比例。
- UI 图标统一使用 Lucide 风格的简洁线性图标，不混用表情符号或多个图标体系。

## 10. 视觉验收基线

- 管理员后台和客户门户必须看起来属于同一个“同舟行商家工作台”产品家族。
- 全局外壳应能明确看到深炭黑工具顶栏、浅色业务导航、浅冷灰工作画布和白色数据面板的组合。
- 随机抽取运营总览、订单列表、库存列表、收款页、批量拿货和客户工作台，不能出现旧版大圆角卡片堆叠风格。
- 页面功能、菜单数量和操作路径与已批准的信息架构一致；不得出现 TikTok Shop 特有业务栏目。
- 桌面端常用管理页面在 1440px 宽度下保持高效密度；客户关键流程在 360、390、430px 宽度下可完整操作。
- 主操作仍使用深海青绿，Logo 红不成为操作色，深炭黑不扩展为全页面深色主题。
- 默认、悬停、焦点、按下、禁用、加载、空、错误和成功状态均使用同一套组件语言。
- 自动化页面截图和浏览器人工验收需要同时覆盖管理员端与客户门户，避免只改全局壳而留下页面内部旧风格。
