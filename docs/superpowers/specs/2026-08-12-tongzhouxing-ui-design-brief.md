# 同舟行跨境 UI 设计简报

状态：视觉方向和设计简报均已确认通过。

## 1. Feature Summary

为同舟行跨境的超级管理员后台和客户门户建立同一套生产级、高保真、响应式产品界面。界面服务于订单、库存、客户、资金、补发和异常处理等高频任务，第一期只提供浅色主题。

管理员以桌面端为主，要求一屏处理较多数据；客户同时使用手机和电脑，上传订单、付款和查看物流必须在小屏上完整可用。

## 2. Primary User Action

用户进入任意页面后，应立即知道当前最需要处理的任务、相关业务状态和下一步操作。

- 管理员的核心动作是发现异常并快速处理，而不是逐页寻找问题。
- 客户的核心动作是选择店铺、上传订单、确认金额并跟踪付款或发货状态。

## 3. Design Direction

### 视觉策略

采用 Restrained 色彩策略：纯白与冷灰构成主要表面，深海青绿只用于主操作、当前选中、链接和键盘焦点，在单屏中保持低占比。Logo 红只属于品牌标志，不用于主操作。

场景定义为“白天办公室里的跨境运营工作台”：光线充足、数据可信、状态清楚、操作迅速，不营造黑色科技大屏氛围。

### 参考来源

- shadcn/ui：开放、可定制和无障碍的组件基础。
- Next Shadcn Dashboard Starter：Next.js 后台框架、筛选表格、表单和错误状态模式。
- Saleor Dashboard：商品、SKU、库存和订单详情的信息组织。
- 飞书：中文表格、表单和操作反馈的熟悉感。

### 方向选择结果

采用三套视觉探针的混合结果：

- A“运营台账”作为全站左侧导航和基础页面结构。
- C“任务指挥栏”作为订单、库存和资金等数据工作区的工具栏、筛选、状态页签和批量操作模式。
- B“商务工作区”的异常上下文只用于运营总览，不作为所有页面的常驻右栏。

## 4. Scope

- Fidelity：生产级高保真，不交付临时后台模板。
- Breadth：完整管理员后台和客户门户的统一设计系统，以及第一阶段所有真实页面。
- Interactivity：最终实现为可真实操作的响应式组件，不是静态图片。
- Time intent：按功能阶段交付，但每阶段页面达到可上线质量后才进入下一阶段。
- Theme：只做浅色主题。
- Accessibility：WCAG 2.2 AA、键盘可达、可见焦点、减少动画模式。

## 5. Layout Strategy

### 全站框架

- 桌面端使用稳定的左侧导航，品牌区只展示正式 Logo 和“同舟行跨境”。
- 左侧导航可以收窄，但关键模块名称默认可见，不依赖只看图标猜功能。
- 页面标题区包含当前位置、业务日期或店铺上下文，以及最多一个主操作。
- 页面主体优先使用分区、分隔线和背景层级，不把所有内容包装成悬浮卡片。

### 运营总览

- 顶部采用紧凑的关键指标带，不使用夸张大号数字卡片。
- 主要区域展示待处理订单、库存预警和每日排行。
- 异常队列作为右侧上下文区域，集中展示极风失败、待核款、付款超时和紧急补货。

### 数据工作区

- 订单、库存、客户和资金页面使用页签、搜索、组合筛选、批量操作和数据表格。
- 筛选状态写入 URL，刷新或分享页面后仍保持相同工作上下文。
- 关键列固定，金额和数量右对齐并使用等宽数字；状态列保持一致位置。
- 详情优先使用页面内分区或侧边抽屉，只有需要阻断用户决策时才使用模态框。

### 客户门户

- 与管理后台共享颜色、字体和组件状态，但采用更大的触控目标和更宽松的局部间距。
- 当前店铺始终清晰可见，上传前必须确认店铺。
- 上传流程使用连续步骤：选择店铺和文件、校验预览、确认金额、付款结果。

### 移动端

- 左侧导航折叠为抽屉，顶部保留当前页面和关键操作。
- 关键触控目标不小于 44px；主要正文不小于 14px。
- 表格按任务选择信息分组、主次字段折叠、固定首列或横向滚动，禁止把桌面表格整体缩小。
- 筛选器在手机端进入全宽抽屉，已启用条件在页面上以可移除标签展示。
- 关键提交动作可在流程底部粘性显示，但不能遮挡表格最后一行或系统提示。
- 使用真实手机宽度覆盖 360px、390px、430px 三档验收。

## 6. Key States

每个页面和组件都必须定义以下状态：

- Default：默认数据、当前上下文和主操作清楚可见。
- Loading：使用与真实内容结构一致的骨架，不在页面中央放单一转圈动画。
- Empty：说明为什么为空，并提供唯一合理的下一步动作。
- Error：说明错误原因、未受影响的数据以及重试或修复入口。
- Success：在原操作位置确认成功，并及时刷新余额、库存或状态。
- Disabled：说明为什么不可操作，不只降低透明度。
- Permission denied：客户访问其他客户数据时返回安全页面，不泄露对象是否存在。
- Offline/API degraded：极风或飞书不可用时保留本地业务数据，展示同步状态和重试入口。
- Large data：订单和 SKU 达到数百或数千条时仍保持筛选、分页和滚动性能。

## 7. Interaction Model

- 普通状态变化使用 150–200ms 的快速过渡；不做编排式页面入场动画。
- 按钮具备默认、悬停、焦点、按下、禁用和加载状态，加载时保持宽度稳定。
- 表格行单击进入详情；复选框只负责批量选择，不能与行跳转冲突。
- 危险操作先显示具体影响范围，确认文案包含对象和后果。
- 保存失败时保留用户输入，错误聚焦到首个无效字段。
- 后台长任务以非阻塞状态显示进度，用户可以离开页面后继续查看结果。
- `prefers-reduced-motion` 启用时移除位移和缩放，只保留即时变化或短淡入。

## 8. Content Requirements

- 页面和按钮使用业务语言，如“确认已收款”“释放库存”“重新推送极风”，不用抽象技术词。
- 状态文案在所有页面保持统一，例如“待付款”“待核款”“待推送极风”“待发货”“已发货”。
- 金额统一显示人民币符号和两位小数；数据库仍使用人民币分整数。
- 库存同时明确区分总库存、锁定库存和可售库存。
- 倒计时显示剩余时间并说明超时后果。
- 错误信息需要包含可行动建议，但不能暴露密钥、完整请求或消费者隐私。
- 正式 Logo 来源为 `C:\Users\AKSSINA\Desktop\同舟行logo.png`，保留透明背景和比例。
- UI 图标统一使用 Lucide 风格的简洁线性图标，不混用表情符号或多个图标体系。
