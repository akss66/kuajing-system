# 同舟行跨境 UI V2 整改设计规范

状态：已确认通过，覆盖管理员端与客户端。

日期：2026-08-13

## 1. 背景与结论

当前系统已经具备统一字体、颜色令牌、响应式壳层、可访问性基础和主要业务功能，但整体仍呈现明显的“开发后台 / 通用管理模板”特征：

- 全局顶栏与左侧品牌区高度、背景和分隔线不连续，像两套界面拼接。
- 管理员一级导航入口过多，日常运营、资金和系统功能长期同级竞争注意力。
- 多数页面重复使用“标题 + 指标卡 + 表单/筛选 + 表格”，缺少业务场景差异。
- 创建、查看、编辑、重置密码、启停等不同频率与风险的动作默认同时展开。
- 账号管理与客户详情页随数据增加会无限膨胀，并产生横向滚动和视觉噪音。
- 客户端虽已有正确业务入口，但内页仍需要同步升级成任务导向的商家工作台。

UI V2 不推翻现有业务能力，也不改写订单、库存、资金、补发、权限和集成状态机。整改重点是全局壳层、信息层级、任务组织、响应式表达和业务页面模式。

## 2. 设计目标

### 管理员端

让管理员进入系统后能够立即判断：

1. 今天业务运行得怎么样。
2. 哪些事情必须优先处理。
3. 去哪里处理，以及处理动作会影响什么。
4. 如何快速扫描大量客户、店铺、SKU、订单和资金记录。

### 客户端

让多店铺客户能够立即判断：

1. 当前有哪些店铺和未完成任务。
2. 应该选品、上传订单、继续草稿、付款还是查看物流。
3. 本次拿货涉及哪些店铺、金额、库存和付款状态。
4. 在手机端被打断后如何继续原任务。

### 共同目标

- 专业、可靠、克制、有明确品牌感，但不追求装饰性“高级感”。
- 桌面端中等偏紧凑，移动端任务优先、易触控。
- 同一事实、状态和操作在两端使用一致的视觉令牌和文案。
- 让页面通过层级和内容类型形成差异，不靠更多边框和卡片分区。

## 3. 本规范与旧规范的关系

本规范继续遵守已批准的品牌、颜色、字体、业务流程和权限边界。

本规范覆盖旧 UI 简报中以下限制：

- “导航信息结构完全冻结”调整为：保留既有路由和业务模块，但允许按任务分组、折叠和调整视觉层级。
- “只更新视觉表达”调整为：允许改变查看、创建、编辑和危险操作的呈现层级，例如列表页、详情页、抽屉和更多操作菜单。

以下内容仍冻结：

- 管理员、超级管理员、客户账号的权限边界。
- 一个客户对应一个客户登录账号。
- 客户与店铺的数据隔离。
- TEMU Excel 导入、多店铺拿货、库存锁定、余额与线下付款、补发、极风履约、飞书同步的业务规则。
- 现有路由语义、审计要求和必须填写操作原因的安全规则。

## 4. Creative North Star

**“同舟行跨境运营指挥台”**

它应当像成熟的跨境商家中心，而不是传统 ERP、大屏驾驶舱或通用 SaaS 模板。

视觉关键词：

- 轻商务
- 商家中心
- 跨境运营
- 数据可信
- 状态明确
- 操作克制
- 桌面高效率
- 手机任务优先

TikTok Shop 商家中心仅作为顶栏、导航密度、数据工作区和控件质感参考，不复制其栏目、角色或业务结构。

## 5. 全局壳层整改

### 5.1 桌面结构

- 顶栏统一为 56px 高，并横跨整个视口。
- 左侧品牌区固定宽 224px，属于顶栏的一部分，不再悬在独立白色区域。
- Logo、产品名和端侧名称在深石墨色顶栏左侧统一对齐。
- 左侧导航从顶栏下方开始，高度为 `100svh - 56px`。
- 顶栏底线与导航起始线全宽连续，侧栏右边线从顶栏下缘连续延伸。
- 主内容从 `x = 224px, y = 56px` 开始，禁止出现 64px 品牌区与 52px 顶栏错位。
- 内容画布背景保持浅冷灰，页面容器按页面类型设置宽度，不再一刀切。

### 5.2 顶栏

- 使用柔和深石墨色，避免近纯黑造成过重视觉压迫。
- 左侧显示品牌与当前端名称；右侧只保留真实可用的全局能力。
- 第一阶段右侧保留通知和账号入口；未实现的帮助、消息入口不占据界面。
- 图标按钮默认无明显描边，悬停和键盘焦点时才显示轻背景或边框。
- 账号下拉统一显示姓名、角色、账号邮箱和退出入口。
- 不在侧栏底部重复展示当前身份卡片。

### 5.3 移动结构

- 顶栏保持 56px，包含菜单、当前上下文、通知和账号入口。
- 导航进入左侧抽屉；抽屉中的分组顺序与桌面一致。
- 页面级主操作根据任务放在标题区或底部粘性操作条，不能与顶栏争抢空间。

## 6. 导航信息架构

### 6.1 管理员端

管理员路由不变，视觉上分为：

1. **工作台**
   - 运营总览
2. **客户与货品**
   - 客户与店铺
   - 商品与 SKU
   - 货盘库存
3. **订单履约**
   - 订单管理
   - 批量草稿诊断
   - 补发管理
4. **资金与数据**
   - 收款与余额
   - 统一结算批次
   - 报表分析
5. **系统管理**
   - 账号管理（仅超级管理员可见）
   - 系统通知
   - 外部集成
   - 系统健康
   - 审计日志

规则：

- 高频业务组默认展开。
- 系统管理默认折叠，但当前路由位于该组时自动展开。
- 当前页面仅允许一个导航项高亮。
- 分组折叠状态在当前浏览器保存。
- 不展示未开放且没有可操作内容的一级入口。

### 6.2 客户端

客户端导航按客户任务组织：

1. **工作台**
   - 客户首页
2. **拿货**
   - 货盘选品
   - 上传 TEMU 订单
   - 多店铺批量拿货
3. **订单与付款**
   - 我的订单
   - 待付款
   - 余额与流水

未开放的“店铺数据”不长期占据主导航；正式可用前可以从产品路线说明或空状态告知。

## 7. 页面类型系统

全站不再强制套用同一个页面模板，而使用五类页面模式。

### 7.1 运营驾驶舱

适用：管理员总览、客户首页。

结构：

- 当日或当前最重要的数据。
- 明确排序的待办与异常。
- 趋势、排行或店铺维度摘要。
- 快捷处理入口。

### 7.2 资源列表

适用：客户、账号、SKU、库存。

结构：

- 标题与唯一主操作。
- 搜索、常用筛选和更多筛选。
- 紧凑列表或表格。
- 批量操作与分页。
- 点击行进入详情或抽屉。

列表页默认不展开编辑器。

### 7.3 业务详情

适用：客户、店铺、订单、结算、补发。

结构：

- 对象身份、状态和主操作。
- 有业务意义的摘要，而非机械 KPI。
- 概览、相关记录、时间线或标签页。
- 编辑进入抽屉；危险操作进入独立区域并二次确认。

### 7.4 操作流程

适用：单店导入、多店铺拿货、付款申报。

结构：

- 当前步骤和整体进度。
- 输入、校验、确认、提交、结果连续呈现。
- 页面离开或刷新后恢复草稿和选择状态。
- 移动端主操作在安全区域内保持可见。

### 7.5 监控与分析

适用：报表、系统健康、集成、审计。

结构：

- 趋势、等级、影响范围和异常队列。
- 表格作为证据明细，不作为页面唯一主体。
- 技术状态必须翻译成运营可理解的影响和下一步。

## 8. 管理员核心页面

### 8.1 运营总览

总览重构为四层：

1. 今日经营：今日订单、成交金额、已发货、待发货。
2. 待办预警：待审核付款、低库存、履约异常、余额不足、导入异常。
3. 经营趋势：近 7 天订单与成交金额、SKU 出库排行、店铺销量排行。
4. 快捷处理：审核收款、异常订单、库存调整、批量诊断。

客户数、店铺数、在售 SKU 等资产数据降为次要信息。

### 8.2 账号管理

列表页：

- 标题区只保留“新建管理员”主操作。
- 使用管理员账号、客户账号、已停用三个标签，并在标签上显示数量。
- 工具栏提供搜索、角色和状态筛选。
- 列表显示姓名、邮箱、角色、所属客户、店铺数、状态、最近登录和行操作。
- 不再为每个账号默认渲染三组编辑表单。

账号抽屉：

1. 账号概览。
2. 基本资料编辑。
3. 登录安全与密码重置。
4. 危险操作区。

规则：

- 超级管理员显示锁定图标和“受保护”标签，只读且不可停用、删除、降级或重置。
- 普通管理员允许修改资料、重置密码和启停。
- 客户账号显示所属客户与店铺数，并提供“查看客户详情”。
- 客户业务资料不在账号管理重复修改。
- 重置密码和启停必须二次确认并填写原因。
- 移动端为账号摘要卡，打开全屏或底部抽屉操作，不横向滚动。

### 8.3 客户与店铺列表

- 标题区提供“新建客户”。
- 创建流程进入抽屉或独立创建页，不长期占据列表首屏。
- 工具栏包含搜索、状态、店铺数和更多筛选。
- 客户列表显示客户、唯一登录账号、店铺数、余额、待付款、近期订单、异常和状态。
- 点击行进入独立客户详情页。

### 8.4 客户详情

顶部：

- 客户名称、编号、状态。
- 编辑客户主操作。
- 其他操作进入“更多”，停用位于危险操作区。

摘要使用有业务价值的数据：

- 可用余额。
- 店铺数量。
- 待付款金额。
- 近期订单量或未完成订单。

页内标签：

1. 概览。
2. 店铺。
3. 订单与补发。
4. 资金记录。

规则：

- 客户资料默认只读，点击编辑后进入抽屉。
- 唯一登录账号只显示摘要和“前往账号管理”。
- 店铺使用紧凑列表，右上角新增店铺。
- 点击店铺进入店铺抽屉，资料编辑与危险操作分区。
- 不默认展开任何客户或店铺编辑表单。

### 8.5 订单、库存与资金

- 订单以状态漏斗、待处理队列和履约阶段为核心。
- 库存以可售、锁定、低库存、覆盖天数和最近变动为核心。
- 收款以待核款、余额风险、批次进度和资金流水为核心。
- 筛选默认只展示最常用 3–4 项，其余进入更多筛选。
- 资金与库存危险操作必须明确影响对象、金额/数量和审计原因。

## 9. 客户端同步整改

客户端与管理端共享：

- 顶栏和导航几何规则。
- 字体、颜色、状态标签、输入框、按钮、抽屉、对话框和空状态。
- 焦点、加载、成功、错误和危险操作规范。

客户端不照搬管理员页面结构，而以任务为中心。

### 9.1 客户首页

首屏顺序：

1. 继续处理：未完成草稿、待付款、付款待确认、待收货或履约异常。
2. 快捷拿货：货盘选品、上传订单、多店铺批量拿货。
3. 店铺摘要：各店铺近期订单、待付款和异常。
4. 资金摘要：可用余额、冻结金额、近期流水。

静态欢迎语与说明降为次要内容。

### 9.2 货盘选品

- 搜索与常用筛选在首屏优先于指标。
- 桌面使用高密度商品列表或表格，移动使用商品摘要卡。
- SKU、规格、可售库存、实际价格和状态保持稳定位置。
- 无库存、低库存和不可售必须同时有文字与语义色。
- 后续拿货动作预留购物清单式选择能力，但本轮不改变既有订单业务规则。

### 9.3 单店订单上传

使用连续步骤：

1. 选择店铺。
2. 上传 TEMU Excel。
3. 校验订单与 SKU。
4. 确认金额和库存。
5. 提交并进入付款/待发货状态。

错误按可修复、需管理员处理和不可提交分类；已上传文件、选择店铺和有效结果在刷新后保留。

### 9.4 多店铺批量拿货

- 列表页首先展示继续上次草稿与新建批量拿货。
- 工作区继续采用按店铺分组、首组展开、其余摘要折叠的移动策略。
- 批次摘要持续展示店铺数、订单数、件数、金额和不可提交数量。
- 提交后以统一结算批次为主线，避免用户在多个订单间反复确认付款。

### 9.5 我的订单与详情

- 使用状态标签页和常用搜索，更多条件进入筛选抽屉。
- 移动端采用订单摘要卡，首屏显示店铺、金额、状态和下一步。
- 详情使用状态时间线表达待付款、待核款、待发货、履约中、已发货、补发和取消。
- 物流、付款和补发都必须显示下一步及异常恢复入口。

### 9.6 付款与余额

- 余额页区分可用余额、冻结金额和资金流水。
- 线下微信付款页面优先显示应付金额、付款状态、申报时限和管理员确认结果。
- 余额充足自动扣款与单笔线下付款使用不同但一致的状态说明。
- 所有金额使用人民币两位小数，并说明锁定、扣款和退款的发生时间。

## 10. 视觉与组件规范

### 10.1 字体

- 全站只使用 `Geist Variable + Noto Sans SC Variable` 的统一字体令牌。
- 禁止页面和业务组件单独覆盖 `font-family`。
- 金额、数量、日期、编号使用等宽数字。
- 页面标题降低夸张感，桌面约 28px，移动约 24px；区域标题 16–18px；正文和表格 13–14px。

### 10.2 色彩

- 深海青绿仍是唯一主操作色。
- Logo 红只用于品牌标志，不进入主按钮、导航高亮或链接。
- 顶栏使用柔和深石墨色。
- 状态色低饱和，并同时使用图标或文字。
- 不使用装饰性渐变、玻璃拟态和大面积彩色背景。

### 10.3 层级与表面

- 默认通过背景、留白、标题和分隔线建立层级。
- 静态区域避免同时使用边框和阴影。
- 抽屉、菜单和对话框可以使用克制阴影。
- `WorkspacePanel` 不再是所有分区的默认答案。
- 数据表格的工具栏、表头和结果区组成一个完整工作区，不堆叠多个白盒。

### 10.4 按钮与操作

- 每个页面标题区最多一个主操作。
- 次要动作使用中性按钮或更多菜单。
- 危险动作使用危险色，但不能与主操作并列同权重展示。
- 所有关键移动触控目标不小于 44px。

### 10.5 抽屉使用

- 简单创建和编辑使用右侧抽屉。
- 复杂、多步骤或需要对照大量数据的任务使用独立页面。
- 桌面抽屉建议 480–640px；移动端使用全屏抽屉。
- 抽屉关闭前若有未保存内容，需要提示。

## 11. 空、错、加载与反馈

空状态分为：

1. 初始空：解释需要先创建或导入什么，并提供唯一主操作。
2. 筛选空：说明当前条件无结果，并提供清空或调整条件。
3. 异常空：说明数据为何不可用、哪些数据未受影响及重试入口。

错误要求：

- 使用中文业务语言，不暴露 Zod、SQL、HTTP 或内部枚举。
- 错误聚焦到首个无效字段，保留用户已输入内容。
- 后台任务失败提供重试或联系管理员入口。

加载要求：

- 骨架与最终页面结构一致。
- 列表筛选时保留工具栏和页面上下文。
- 提交按钮保持宽度稳定并防止重复提交。

成功反馈：

- 在原操作位置确认成功。
- 同步刷新状态、余额、库存和最近操作记录。

## 12. 响应式规则

- 验收宽度：1440px、1920px、430px、390px、360px。
- 桌面资源列表允许高密度表格，但禁止整行表单展开。
- 移动端资源列表改为摘要卡或主次字段折叠。
- 移动筛选进入全宽抽屉，已启用条件以可移除标签展示。
- 移动详情页主操作靠近拇指区域，危险操作不与主操作相邻。
- 所有页面 `documentElement.scrollWidth - clientWidth <= 1px`。
- 不能通过缩小到 12px 以下字体解决空间问题。

## 13. 可访问性与安全

- 目标 WCAG 2.2 AA。
- 所有操作键盘可达，焦点环清晰。
- 抽屉和对话框正确管理焦点、标题与关闭行为。
- 状态不能只依赖颜色。
- 表格与移动摘要卡需要表达同一业务事实。
- 危险操作必须展示对象、后果、审计原因和确认步骤。
- 普通管理员不可通过 UI 或 Server Action 进入超级管理员治理能力。
- 客户端不得展示其他客户、店铺、订单和资金数据。

## 14. 数据与后端边界

UI V2 第一批不改变核心数据库结构和业务状态机。

允许新增只读查询或聚合模型，以支持：

- 今日经营指标。
- 待办和异常数量。
- 客户余额、待付款、近期订单。
- 店铺维度摘要。
- 近 7 天趋势和排行。

所有数据必须从真实数据库读取，不使用硬编码演示统计。若某项指标暂时没有可靠数据来源，应隐藏或标记为后续，而不是展示伪数据。

## 16. 验收标准

### 全局

- 顶栏全宽连续，品牌区与右侧工具区高度、底线和背景完全对齐。
- 导航最多只高亮一个入口，分组清楚且系统组可折叠。
- 全站没有页面级字体覆盖，Logo 红不作为操作色。
- 不再出现无意义的 KPI 重复和层层白色矩形。

### 管理员端

- 账号列表不再默认展开编辑、重置和启停表单。
- 客户详情默认只读，店铺列表不默认展开编辑器。
- 总览能够直接显示当日待办和异常优先级。
- 高频筛选默认不超过 4 个可见条件。

### 客户端

- 首页优先显示未完成任务和快捷拿货。
- 单店和多店拿货能够在手机端完整完成。
- 订单详情清楚显示付款、库存、履约和补发时间线。
- 余额、冻结和线下付款状态含义明确。

### 自动化与人工验收

- 核心管理员和客户端路由覆盖桌面与 390px 视觉回归。
- 关键移动流程额外覆盖 360px 和 430px。
- axe serious/critical 为 0。
- 无横向页面溢出。
- 无 hydration、page error 或未处理 console error。
- 账号、客户、店铺、库存和资金危险操作具有明确确认与审计原因。

## 17. 非目标

- 本轮不接入极风和飞书授权资料。
- 不开发行业资讯、AI 选品、广告费或平台佣金。
- 不新增深色主题。
- 不更换 Logo，不把 Logo 红改成主操作色。
- 不为了 UI 改造改变库存扣减、付款、退款、补发和履约业务规则。

## 18. 已确认决策

- 整个系统采用 UI V2 结构性整改，不只做表面美化。
- 管理员端和客户端同步整改。
- 顶栏与侧栏必须重新实现为连续、像素级对齐的统一壳层。
- 账号管理采用紧凑列表与详情抽屉。
- 客户使用独立详情页；店铺管理使用列表与抽屉。
- 客户端共用视觉系统，但使用客户任务导向的信息结构。
- 先完成 UI 设计与实施，极风和飞书授权资料后续接入。
