# 飞书字段对齐与运营界面整改设计

日期：2026-08-14
状态：已确认设计方向，等待书面规范复核

## 1. 目标与用户

本次整改服务于两类高频用户：管理员需要快速维护货盘、账号与库存；合作客户需要在电脑和手机上查看货盘并选择 SKU。整改不改变现有路由、权限、订单状态机或飞书业务表，只修正信息层级、响应式布局和飞书字段在系统数据库及界面中的表达。

成功标准：

- 管理员能在 SKU 页面完整核对飞书货盘的 74 个来源序号及其全部 SKU 变体。
- 客户货盘不再发生规格文字与价格、库存或状态重叠。
- 账号管理的表头、数据和操作列始终对齐，桌面端不出现无意义滚动控件。
- 左侧导航能快速识别分组、当前分组和当前页面。
- 飞书始终只读；系统只把飞书数据迁移和更新到自身 PostgreSQL 数据库。

## 2. 数据事实与字段映射

飞书当前货盘是字段口径的权威来源。系统必须保留以下映射：

| 飞书字段 | 系统结构化事实 | 展示说明 |
|---|---|---|
| 序号 | 商品来源序号 `sourceSequence` | 同一序号下多个 SKU 变体共享 |
| SKU | `skus.skuCode` | 唯一 SKU 编码 |
| 图片 | SKU 图片资产 | 每个 SKU 一张图片 |
| 名称 | `products.name` | 商品名称 |
| 采购价 | SKU 默认拿货价，精确到毫元 | 保留三位小数，不使用浮点数 |
| 总库存（份） | 库存总量 | 来自库存余额，不由状态推导 |
| 链接文字 | 商品独立 `linkText` | 不再复用商品描述 |
| 链接地址 | 商品/SKU 外部链接 | 与链接文字组合展示 |
| 规格 | `skus.specification` | 规格主值 |
| 颜色 | `skus.color` | SKU 属性 |
| 组合销售 | `skus.combination` | SKU 属性 |
| 重量 | `skus.weightGrams` | 克重结构化保存 |
| 状态 | `skus.saleStatus` | 人工可售状态独立于库存 |
| 货品价格 | 商品独立 `cargoUnitPriceMilliYuan` | 与采购价不同的第二个价格，精确到毫元 |

`sourceSequence`、`linkText` 和 `cargoUnitPriceMilliYuan` 是本次新增的长期结构化字段。现有 140 个 SKU 将通过飞书只读重新同步补齐，目标是恢复为 74 个来源序号分组。同步必须幂等；不得创建重复商品、重复 SKU 或重复图片资产。

## 3. 管理员商品与 SKU 页面

桌面端采用同一语义表格上下文，但不机械复制飞书的 13 列宽表。信息组合如下：

1. **序号**：来源序号，变体共享但每行仍可读。
2. **商品**：图片、名称和 SKU，形成最强识别区。
3. **规格/属性**：规格为主行；颜色、组合销售、重量为带标签次行。
4. **采购价**：默认拿货价。
5. **总库存**：真实库存总量。
6. **可售库存**：总量减有效预占。
7. **货品价格**：飞书独立第二价格。
8. **状态**：人工可售/不可售。
9. **链接**：链接文字与安全外链入口。

页面支持搜索 SKU、名称、规格和来源序号。长规格允许最多两行换行，不得侵入相邻列。金额、库存和序号使用等宽数字与右对齐。移动端改为卡片，顺序固定为商品识别、规格属性、两个价格、库存、状态和链接，不做横向缩小表格。

## 4. 客户货盘

客户页面只展示完成选品所需信息：商品图片/名称、SKU、规格属性、客户实际拿货价、可售库存、状态和商品链接。管理员内部的来源序号、总库存、采购成本口径和货品价格不在客户页额外暴露。

客户实际拿货价继续遵守现有价格优先级：客户专属价、临时成交价、默认拿货价。规格列必须以 `specification` 为主值，商品名称或 SKU 名称不能冒充规格。

状态拆分为两个事实：

- 人工状态：`SELLABLE` / `NOT_SELLABLE`。
- 下单可用性：人工可售且可售库存大于零。

因此“不可售”和“库存不足/售罄”必须使用不同文案。人工不可售但仍有库存的 SKU 仍可被客户看见，但不能加入拿货单。

## 5. 账号管理

桌面端改为真正的语义表格，表头和数据共享同一列定义：姓名、邮箱、角色、所属客户、店铺数、状态、最近登录、操作。邮箱允许安全断行，操作列固定窄宽。标签栏只在小屏允许横向滚动，桌面端不得显示异常滚动按钮或滚动条。

移动端保留摘要卡与详情抽屉，不把桌面表格横向压缩。停用、恢复、重置密码等现有权限与审计语义保持不变。

## 6. 左侧导航

不改变现有菜单、顺序和路由，只增强层级表达：

- 分组标题与叶子链接使用不同字号、字重、缩进和纵向节奏。
- 当前分组标题加深，当前叶子项继续使用唯一高亮和 `aria-current="page"`。
- 系统管理默认折叠；当前页面属于该组时自动展开。
- 移动抽屉沿用相同分组顺序和键盘焦点顺序。

## 7. 状态、边界与错误恢复

- 飞书读取失败：不修改现有系统货盘，显示只读同步失败与可重试入口。
- 字段缺失：预检阻止覆盖，并列出序号/SKU/字段原因。
- 图片缺失：保留 SKU 与业务字段，显示明确占位，不创建伪图片。
- 空数据：管理员页面显示来源状态与重新只读预检入口；客户页面显示暂时无可选货盘。
- 长文本：规格、链接文字和邮箱必须有受控换行/截断与完整可访问名称。
- 所有危险操作、权限、审计、库存预占和订单状态机保持现状。

## 8. 响应式与无障碍

- 验收宽度：1440×900、1920×1080、430×900、390×844、360×800。
- 桌面表格不能出现页面级横向溢出；移动端核心页面不能依赖横向滚动完成任务。
- 关键触控目标至少 44px。
- 状态不能只靠颜色；表格、卡片、外链和折叠组必须有正确语义与键盘焦点。
- 目标为 WCAG 2.2 AA，axe serious/critical 为 0。

## 9. 测试与验收

实施必须遵守 RED→GREEN：

- 集成测试：新增字段迁移、74 个序号/140 个 SKU 幂等回填、人工状态与库存独立、链接与货品价格精确保存。
- 单元测试：导航当前组、账号语义表格、客户长规格、不可售与售罄、管理员完整字段视图。
- E2E：管理员 SKU、账号管理、客户货盘在桌面和三档手机宽度下无重叠、无页面级横向溢出、无控制台/水合错误。
- 库存集成测试：方向与正整数校验、结构化原因/备注、锁定库存并发下限、自动/手工发货来源分离、盘点批次，以及全量筛选与分页。
- 库存 E2E：两个一级视图、行内 `+ / -`、实时预览、防重复扣减提示、完整流水、桌面与 360/390/430 移动适配。
- 视觉基线：覆盖长规格、长邮箱、多 SKU 变体、三位小数价格、人工不可售但有库存。
- 最终只读审计：生产配置中的飞书写入开关继续为 `false`，任何整改流程都不得调用飞书写接口。

## 10. 库存工作区

库存模块只保留两个一级视图：`实时库存` 与 `库存流水`。不得新增独立的“批量盘点”一级入口；批量粘贴若保留，只能是实时库存内的次级动作。

实时库存中每个 SKU 行内提供 `+ / - 调整` 作为主操作。管理员先选择增加或减少，再输入正整数数量：增加默认结构化原因为 `补货入库`，减少默认结构化原因为 `线下发货/人工出库`。界面实时展示调整前总库存、变化量、调整后总库存、订单锁定、当前可售与调整后可售；减少后的总库存不得低于订单锁定量，客户端预览和服务端事务都必须校验该不变量。每次调整必须结构化保存原因，并允许填写备注。

`线下发货/人工出库` 只表示未经过本系统订单的线下发货或历史补录。选择该原因时显示简短防重复扣减提示：系统内订单会在极风/履约确认发货后自动生成 `系统发货扣减`，管理员不得再次手工调整。自动发货与手工出库必须以不同的移动类型、来源和关联单据记录，不能仅靠展示文案区分。

`设置为实际库存` 仅作为低频次级盘点模式，不抢占 `+ / - 调整` 主操作，也不形成第三个一级视图。盘点产生的变动必须关联可追溯的盘点批次；实际值与当前值相同可以明确提示“无变化，不生成库存流水”。

库存流水是独立、明显的一级入口，不是实时库存页面底部的“最近 8 条”。它支持 SKU、时间、类型、操作人筛选与分页，逐条展示前值、变动、后值、结构化原因、备注、操作人、来源、时间，以及按类型白名单解析的关联订单、补发、飞书迁移或盘点批次。自动 `系统发货扣减` 与手工 `线下发货/人工出库` 必须可筛选、可辨认，便于后续分析。

桌面端使用语义表格，360/390/430 宽度使用任务顺序明确的卡片或抽屉；页面不得横向溢出，触控目标、键盘焦点和错误提示满足本规范的无障碍要求。

## 11. 非目标

- 不改飞书业务表，不建立系统到飞书的写回。
- 不改变订单、结算、极风/履约驱动的系统发货扣减、补发、权限或审计语义；本次仅补齐人工库存调整与库存流水的可用性和可追溯性。
- 不重新设计整套信息架构，不复制 TikTok Shop 的业务栏目。
- 不通过缩小字号、强制单行或整页横向滚动掩盖布局问题。
